# V4 独立数据资源与受管研究设计

## Status

本文件记录 V4 已确认的产品需求，尚未实现。V3 代码和现行接口仍以 `docs/development-status.md` 记录的合同为准。
V4 是空库新基线，不迁移、双读或兼容 V3 数据库与持久化数据。

## Relationship to V3

V4 只改变本文件明确描述的数据资源、研究输入确认、脚本生成/修正/执行和直接相关界面及合同。认证与固定用户、
会话和聊天历史、模型工作区与案例导入、自然语言优先边界、历史搜索与分页、结果查看/下载/分析/比较、ECharts
受控可视化、用户隔离、tensoreval adapter 边界、Parquet/CAS、调度并发、错误响应和其他未在本文改变的行为，均
沿用实施 V4 时 V3 当前设计文档和已验证代码合同，不在本需求讨论中重新选择默认值或另造一套规则。

“沿用 V3”只表示产品行为与安全边界继续有效，不表示保留 V3 表结构、路由内部实现、兼容分支或历史数据。V4 可以
按最终需求重新设计空库 schema 和内部代码；本文与 V3 合同发生明确冲突时以本文为准，没有明确冲突时以 V3 当前
合同为准。详细实施方案必须列出被 V4 改变的公共接口、消息、状态和错误码，并对所有未改变的 V3 功能执行回归
验证，不能因重构静默删除旧功能。

## Intent

负荷预测、气象、价格曲线、测量序列和其他辅助 DataFrame 不属于配电网模型，也不应为了参加一次仿真而进入
模型草稿和模型版本。V4 必须把这类数据作为独立的数据资源管理，使用户可以上传、查找、查看、下载、
删除、重新上传，并通过自然语言要求 Agent 将指定资源用于仿真或分析。

模型版本只保存电网模型本身。数据资源没有面向用户的版本树；运行仍必须冻结实际输入，使历史结果可复现。

## Current gap

V3 把 CSV、Excel 和 Parquet 全部送入模型导入流水线。确认后候选表进入可变草稿，发布后进入模型版本；确认前
只有当前页面的导入卡可见，普通数据没有持久文件列表、独立预览入口或运行输入绑定。这不满足辅助数据的管理
和复用需求，V4 不保留该限制。

## Chosen approach

采用与模型工作区并列的“数据资源库”：模型 DataFrame 继续由模型草稿和版本管理，辅助 DataFrame 与本地参数
DataFrame 都作为同一种普通资源管理。上传内容必须先确定用途；可从文件名、Excel 工作表名、列名和用户自然语言意图推断，
无法可靠判断时要求用户确认，不能静默把辅助数据或参数并入模型版本。

当前 `import_dss` 静态导入会返回 21 张 DataFrame，但其中 `para` 表示求解参数 Struct，不是电网模型。V4 必须在
adapter 输出进入工作区以前把它拆开：`bus` 至 `storage` 的 20 张网络表可以进入模型草稿和模型版本，`para` 永远
不能进入 draft/model version，而是作为当前会话的普通本地数据资源保存为规范 Snappy Parquet。案例库应用、
DSS/bundle 导入和其他使用同一静态导入 profile 的入口都执行相同拆分，不能因来源不同恢复 21 张模型表。

从“模型工作区”或模型缺失提示发起的上传把候选用途预填为模型表；从“数据文件”或研究 Data 输入缺失提示发起的
上传预填为数据资源；对话中的通用附件则根据当前 engine snapshot 的模型 schema、实际表头/dtype 和用户意图推断。
预填只减少操作，不能覆盖明显冲突。一个批次同时包含模型表和辅助数据、候选同时匹配两类 schema、或推断置信度
不足时，批次进入 `awaiting_purpose` 并显示逐候选用途确认卡；每项可以选择“模型表”“数据资源”或“不导入”，
卡片必须展示推断依据和冲突，不能静默分类。

用户确认用途后，服务把同一来源批次拆成模型子批次和资源子批次。模型子批次沿用 V3 模型导入、草稿 revision 和
冲突规则，资源子批次沿用本文的数据候选原子发布规则并可同时包含辅助数据和 adapter 明确产出的 `para` 普通资源；
两个子批次各自在内部全成或全败，但彼此是独立事务，一方失败不回滚另一方已经合法发布的内容。界面必须分别显示
两方状态、成功项和诊断，不能把跨域部分成功显示为整个批次成功。此时总批次进入可恢复的
`partially_confirmed`，已成功子批次不可重复发布，用户修正后只重试失败子批次。两方引用同一原文件时复用来源
artifact；成功侧需要的来源转为长期引用，失败侧仍需的暂存和配额预留继续保留，直到失败侧成功、放弃或过期后才
结算；只有两方都没有发布且候选最终放弃或过期时才清理全部暂存来源。

考虑过但不采用以下方案：

- 所有 DataFrame 继续进入模型版本：实现简单，但模型版本会被预测数据等高频变化污染。
- 只保存原始文件而不建立 DataFrame 资源：无法统一预览、受控读取、Agent 查询和 tensoreval 输入。
- 独立数据资源库：增加一种明确的资源类型，但职责清晰，并允许模型版本与运行输入分别演进；本版本采用此方案。

## Resource identity and naming

每张可独立使用的 DataFrame 对应一个普通本地数据资源，不再设置参数预设等资源种类，至少包含：

- `resourceId`：上传规范化成功后由后端生成的 opaque UUID/ULID；用户、浏览器和 LLM 不得构造或提交服务器路径。
- `displayName`：用于界面展示，来源于原文件名和可选的 Excel 工作表名；修改展示名不改变数据内容。
- `alias`：合法且在当前会话中唯一的 tensoreval 变量名。后端根据文件名或
  工作表名生成默认值；名称非法或冲突时生成 `data_<shortId>`。用户可通过自然语言修改别名，服务端负责语法、
  保留字和唯一性校验。静态导入的 `para` 默认使用 `para` alias，并按普通资源参加冲突校验和运行输入解析。
- `artifactId`、`contentHash`、schema、row count、格式、创建时间和来源摘要：只由服务端维护，不向客户端暴露
  物理存储路径。

静态导入产生的 `para` 资源保存其 Struct `schemaRef`、来源 import/case/upload batch、原始输出名和与同批模型的来源
关联，但这些只是普通资源的 schema 与血缘元数据，不形成独立的“参数预设”资源类型。候选确认卡把 `para` 固定路由
到资源子事务并默认选择，用户可以不导入，但不能改成模型表。普通 CSV/Excel/Parquet 上传仍只在“模型表”“数据资源”
“不导入”之间选择。

`para` 在“数据文件”中与其他资源使用相同的查看、下载、删除、重新上传和覆盖能力。参数卡可以读取 schema 兼容的
`para` 资源并编辑字段；用户在最终配置摘要中确认覆盖后，后端以普通资源 replacement 事务发布新的规范 Snappy
Parquet、转移原 alias，并保留旧 artifact 供已有运行引用。这里的“覆盖”是用户可见资源的当前内容更新，不会原地
改写已经被历史运行引用的 artifact，也不建立面向用户的模型式版本树。任何普通资源只要被当前 snapshot 识别为
某个 `inputKind=struct` 的单行 schema，就可以从资源详情打开同一参数卡进行修改，不依赖专用资源类型或文件名。

用户明确把候选标为“数据资源”后，不要求它在上传时匹配任何当前研究门面的 `schemaRef`。服务端只要能够安全解析
并规范化为受支持的 Parquet DataFrame，就按实际列名和 dtype 保存为通用资源，`declaredSchemaRef` 为空，并在界面
显示“通用数据”而不是伪造一个最相似的业务类型。完全匹配某些目录 schema 时可以保存按 snapshot/schemaRef 计算的
兼容性记录，但不能因此改变资源身份或把推断当成用户已选择的研究用途。

通用资源可以先上传、查看、下载、重命名 alias，并在手写脚本中按 alias 使用。以后进入某个受管研究时，再针对该
门面的具体 Data 输入 `schemaRef` 做兼容校验：完全兼容时直接选择，需要受控转换时展示映射卡并创建派生资源，无法
安全映射时要求用户修正或重新上传。缺少当前门面匹配本身不是上传失败，只有文件无法形成合法 DataFrame、违反
安全限制或规范 Parquet 写入失败时才拒绝资源子批次中的普通数据候选。

通用数据资源也可以直接作为 V3 既有自然语言分析、派生表格和受控 ECharts 可视化链路的来源，不要求先选择
`ds_*` 研究门面。用户引用唯一资源和明确列时直接沿用既有分析流程；资源、时间列、数值列或聚合方式存在歧义时，
在对话中显示资源/字段选择卡，不能猜测。分析工具只接收稳定 `resourceId` 和受控 spec，输出继续是不可变派生
数据集、图表数据或物化分析，并记录源资源 ID/hash 与当前分析合同；不向 LLM 或浏览器暴露路径、SQL 或任意
ECharts option。除新增的数据资源来源类型外，分析执行、历史、错误、分页和可视化行为沿用 V3 合同。

`displayName` 与 `alias` 用途不同：中文名称可以完整保留用于展示，普通数据脚本输入始终使用受控 alias。普通数据
上传始终创建新的 `resourceId`，不会因为文件名相同就替换现有资源。用户从已有普通数据资源发起“重新上传”时，
新文件仍创建新资源，不覆盖
旧内容或建立面向用户的版本树；新资源处理成功并经用户确认替换后，后端在一个事务中把旧资源的 alias 转移给
新资源，并给旧资源分配 `data_<shortId>` 形式的可用备用 alias。用户取消、处理失败或事务冲突时，旧资源及其
alias 保持不变。

alias 的唯一性范围是当前会话全部未删除的数据资源，而不是某一次运行临时选择的输入集合。
标识符语法、大小写
归一和 RSS 保留字来自本次 engine resource snapshot；alias 还不得与目录声明的模型表名、结果名、
研究函数名以及后端保留的临时变量命名空间冲突。服务端使用归一后的标识符建立唯一约束，不能只依赖前端检查；
默认 alias 冲突时生成新的 `data_<shortId>`，用户显式指定冲突名称时返回稳定 `resource_alias_conflict` 和冲突类别。

每次服务以新 engine snapshot 启动时重新校验所有未删除资源的 alias。原来合法但被新目录
加入保留集合的 alias 只被
标记为 `needs_rename`，资源内容、身份和历史运行保持可读，不自动改名或改写已有脚本；该资源在重命名前不能绑定到
新研究，也不能解析为新运行输入。研究确认或脚本“运行”遇到此状态时返回 `resource_alias_conflict`，指出当前 alias、
冲突对象和 snapshot，用户通过自然语言显式重命名后才能继续。重命名会使仍引用旧 alias 的未确认配置失效，已有
脚本内容保持不变，后续再次运行旧脚本时按其旧 alias 正常报告缺失输入。

## Storage and lifecycle

CSV 和 Excel 在接收后规范化为 Snappy Parquet；Parquet 也必须通过 schema、压缩、大小和安全检查。规范化后的
Parquet 是计算和表格预览的事实来源。用户上传的 CSV、Excel 和 Parquet 原始字节同时作为不可变来源 artifact
长期保存并计入用户配额，记录原始文件名、内容 hash、大小、媒体类型、Excel 工作表和导入诊断等来源摘要。
对具有上传来源的数据资源，数据文件界面分别提供“下载原文件”和“下载规范 Parquet”；原文件只能用于下载、
重新映射和来源审计，不能绕过规范化直接成为 tensoreval 输入。由结果或分析提升且没有上传原文件的数据资源只
提供规范 Parquet 下载，并显示可访问的来源运行或分析引用，不能伪造“原文件”入口。

同一个 Excel 工作簿产生的多张 DataFrame 资源共享一份原文件 artifact，各自引用自己的规范 Parquet；相同内容的
重复上传继续按 hash 去重，但每个资源的身份和来源记录保持独立。确认列映射产生的派生资源必须沿血缘引用源资源
及其原文件，不能复制一份无法关联的新来源。删除一个资源只释放该资源直接持有的引用；原文件仍被其他工作表、
派生资源或保留的历史血缘引用时继续存在，只有当前用户的最后一个资源或历史引用释放后才减少配额并允许物理
回收。上传的 Parquet 已经符合规范格式和压缩合同时，原文件与规范 artifact 可以通过相同内容 hash 复用。

V4 的模型包和独立数据资源上传统一使用现有可配置安全门禁：`UPLOAD_SINGLE_FILE_LIMIT_BYTES=52428800`
（50 MiB）、`UPLOAD_BATCH_LIMIT_BYTES=524288000`（500 MiB）、`ARCHIVE_MAX_ENTRIES=1000`、
`ARCHIVE_MAX_EXPANDED_BYTES=2147483648`（2 GiB）和 `ARCHIVE_MAX_COMPRESSION_RATIO=100`。限制按接收的原始
字节和安全解包过程计算，不能以压缩后大小规避；流式接收一旦确认超限立即停止继续写入并清理暂存内容。单文件、
整个批次或压缩包任一门禁失败时整次上传失败，不创建可见数据资源、模型候选或部分 alias，分别返回稳定且可区分的
`upload_file_too_large`、`upload_batch_too_large` 或 `archive_limits_exceeded` 诊断。

数据文件上传先产生同一批次中的候选 DataFrame，不立即发布资源。每个 CSV 或 Parquet 文件形成一个候选；Excel
工作簿按工作表拆分，每个非空可见工作表形成一个默认勾选候选，空工作表跳过，隐藏工作表默认不选但必须在展开的
工作表列表中标明隐藏状态并允许用户主动选择。候选确认卡显示来源文件、工作表、推断列名/dtype、行列数、有限
样例、诊断、建议 display name 和 alias，提供“全选/取消全选”和逐项选择；用户可以在确认前修改合法且不冲突的
alias。列名和 dtype 推断以实际表头和单元格为依据，不能仅用文件名或工作表名猜测 schema。

用户确认后，后端在一个发布事务中为全部已选数据候选创建普通数据资源、规范 Parquet、来源引用和 alias；静态导入
的 `para` 同样创建普通资源，并附带 `schemaRef` 与同批导入来源。任一已选候选的解析、schema、安全、配额或 alias
校验失败时整批不发布，未选候选不创建资源。失败卡必须定位到具体文件、工作表
和字段，用户修正选择或重新上传后可再次确认。批次确认前的原始字节只处于受限暂存区；确认成功后才成为长期来源
artifact，放弃、超时或失败批次按暂存清理策略删除，不能形成数据文件列表中的半成品资源。若上传入口来自某个缺失
Data 输入，该输入只能在批次发布成功后绑定兼容资源，上传动作本身仍不构成最终研究配置确认。

这里可再次确认的发布校验失败不是批次终态：两个子事务都未发布时回到 `ready_to_confirm` 并保存逐候选诊断；仅一侧
发布时保持 `partially_confirmed`。只有来源损坏、暂存丢失或无法恢复的处理错误才进入终态 `failed` 并按清理规则
释放暂存和预留。前端必须区分“修正后可确认”和“必须重新上传”，不能把可重试失败永久锁死或把终态失败再次提交。

CSV/Excel 的分隔符、字符编码、表头行、数字小数点与千分位、日期时间格式、时区以及 Excel 数据范围可以由服务端
从原始字节和表头可靠推断时，候选卡直接预填并显示推断值与置信诊断。任一设置存在多个同等候选、混合格式或会
改变列解释时，批次进入 `awaiting_parse_settings`，在对话中显示独立的“文件解析设置”卡片并阻止资源发布；不能
静默采用服务器 locale、当前时区或解析库默认值。卡片只接受服务端允许的枚举、格式模板、行号和单元格范围，不能
提交代码、SQL、正则脚本或任意表达式。

用户确认解析设置后，后端重新解析相应文件并刷新列名、dtype、行列数、样例和诊断；此前基于旧解析结果的列映射、
资源选择和研究配置全部失效。最终资源保存规范化解析 spec、解析器版本、原始文件 hash 和诊断，使同一来源能够
解释为何得到当前 Parquet。该卡片只控制上传文件如何变成 DataFrame，不生成 `ds_*` 的 Struct DataFrame，也不能
被当作研究参数确认；完成文件解析后仍须分别完成资源发布和最终研究配置确认。

模型和数据上传的未确认候选批次默认保留 24 小时，由 `.env` 的 `UPLOAD_STAGING_TTL_HOURS` 配置。接收暂存字节
前必须在用户配额中原子预留等量 `reservedBytes`；存储告警和硬限制按已发布逻辑字节与预留字节之和计算，避免通过
大量不确认批次绕过配额。候选详情返回稳定批次 ID 和 `expiresAt`，页面刷新、切换会话和服务重启后可恢复同一候选
卡；启动恢复必须重新核对暂存文件、预留值和数据库状态，不能重复计费或留下无主文件。

用户确认时，在一个事务中把所选来源和规范化结果提交为正式 artifact，并释放对应预留；内容 hash 已由当前用户
计费时只增加引用，不重复增加正式逻辑字节。用户主动放弃或 TTL 到期后，批次进入终态、清理全部暂存内容并释放
预留。过期卡返回稳定 `upload_batch_expired`，不能继续确认、绑定或恢复，用户必须重新上传。确认、过期、放弃和
服务恢复之间使用幂等终态转换，不能同时发布资源又释放其配额，也不能因重复请求重复扣减预留。

Excel 解析器不得执行公式、宏、脚本、数据连接或外部链接，也不得为取得值访问网络或本地引用文件。公式单元格只
读取工作簿上次保存时已有的缓存值，候选卡必须显示公式单元格数量并提示缓存值可能对应上次计算时间；规范 Parquet
只保存读取到的值和来源诊断，不保存可执行公式。目标 schema 的必填单元格含公式但没有可用缓存值时，该候选使用
稳定错误 `excel_formula_value_missing` 失败，并提示用户在 Excel 中重新计算后保存或导出为纯值 CSV。非必填单元格
缺少缓存值时规范为 null，并在确认卡中显示工作表、单元格位置和数量警告。原始 Excel 仍按来源 artifact 原样保存和
下载，但服务端任何后续预览、映射或研究输入都只能使用已规范化的非可执行 Parquet 数据。

数据资源属于认证用户并归属一个会话；所有查询显式接收 `UserId`，跨用户和不存在资源统一返回 404。资源计入
用户存储配额。V4 默认每个用户最多占用 20,000 个不同内容的 artifact 和 21,474,836,480 字节（20 GiB）逻辑
存储，分别由 `.env` 的 `USER_ARTIFACT_LIMIT` 和 `USER_STORAGE_LIMIT_BYTES` 配置；同一用户对相同内容 hash 的
多个引用只计一个 artifact 和一份字节，不同用户仍分别计入各自配额。`STORAGE_WARNING_RATIO` 默认 0.8，达到
任一硬限制的 80% 后在数据文件、模型和运行入口持续显示用量告警，但不阻止操作。配额不按文件数量、会话数量、
保存天数或最后访问时间自动淘汰，系统也不得为了新运行静默删除旧历史。

达到硬限制后，新的上传、派生资源、脚本 attempt 和结果发布使用稳定错误 `storage_quota_exceeded` 原子失败；
已有会话、脚本、数据资源和结果仍可查看、下载和删除。用户确认删除资源后，资源立即从资源库隐藏并释放资源
自身的 artifact 引用；只有当前用户对同一 artifact 的最后引用释放后，才减少该用户的 artifact 数和逻辑字节，
物理 CAS 内容则等待所有用户引用释放后回收。运行产生的多个结果必须作为一个发布事务检查配额，不能只发布能
放下的一部分。配额错误属于存储条件，不进入脚本自动修正；受管工作流保留最后候选并提示用户释放空间后
“重新尝试”。

单独删除资源必须先显示不可逆确认框，至少列出 display name、资源类型、可选 alias、schema 摘要、大小，以及尚未
确认的研究配置、冻结工作流和历史血缘中的引用影响。确认删除后资源立即从资源库隐藏；普通数据同时从 alias 解析
中隐藏。所有引用该稳定 `resourceId` 或依赖其 alias 的未确认配置失效并要求重新选择；后续成功脚本点击“运行”时
若所需普通数据 alias 已不存在，
按资源缺失返回明确诊断，不能静默绑定其他资源。已经确认并冻结输入的非终态工作流继续使用其冻结引用，已有运行、
结果和派生历史继续可读且可复现，删除资源不取消工作流，也不破坏历史。取消确认不产生任何变化；删除请求必须
幂等，重复提交不得重复释放引用或配额。

删除会话属于固定的高频历史管理操作，但必须先显示不可逆确认框。确认框至少列出该会话将被隐藏的模型版本、
数据资源、脚本、运行、结果/分析 artifact 数量和当前逻辑占用空间，并明确正在运行的工作流也会取消。用户确认后，
后端在事务中把会话标记为删除中并立即从会话列表和所有普通读取接口隐藏，同时阻止该会话创建新消息、资源或运行，
再按与用户取消相同的规则终止进行中的 Agent 请求和 tensoreval 进程组、清理未发布目录。删除与工作流成功发布竞争
时以第一个原子终态转换为准；会话进入删除中后不得再发布结果。

后台收敛后删除该会话拥有的模型、数据资源、脚本、运行和结果记录，并按引用计数释放 artifact 和用户配额。
同一用户其他会话中的物化分析、比较或其他历史血缘仍引用某个 artifact 时，该内容和最小来源墓碑继续保留，直到
最后引用释放；删除会话不能破坏仍可见的派生结果，也不能让已删除源资源重新出现在普通列表。删除接口必须幂等，
确认后刷新或重复请求不会恢复会话或重复扣减引用；删除中的会话对普通读取统一表现为 404。

运行记录列表中的每条终态记录提供固定“删除”按钮。第一次点击只请求删除影响预览并打开确认框，至少显示运行标识、
状态、结果数据集数量、预计释放空间，以及仍被提升资源、物化分析、视图或比较引用的结果数量；用户确认后才执行。
queued/running 或仍属于非终态受管工作流的记录不能删除，返回稳定 `run_busy` 并提示先等待或取消。任一结果正被
queued/running 分析消费时沿用 `result_busy` 阻止整次删除，不能只删除其中空闲的结果。

确认删除后，后端在一个事务中把运行记录和该运行直接产生的全部未删除结果数据集写成 tombstone，并立即从运行历史、
结果列表、rows 和 download 接口隐藏；请求必须幂等，跨用户与不存在对象仍统一 404。删除不级联到脚本、模型版本、
输入数据资源、已完成的物化分析/视图/比较或由结果提升得到的本地资源。后者继续可读，并通过保存的运行/结果墓碑展示
来源已删除；其 artifact 引用继续保留内容。运行及结果直接持有的 artifact 引用在事务后释放，只有引用归零的内容才
回收并减少配额。对话中的历史消息和脚本卡不删除，原结果入口刷新后显示该运行已删除。

影响预览使用短期、用户/运行/影响集合绑定的 token；确认时重新计算结果集合、busy 状态和引用影响，变化时沿用
`deletion_impact_changed` 要求重新确认。删除成功后前端原子移除该运行、关闭正在查看的所属结果，并失效运行、结果、
存储用量和相关血缘缓存。

每条运行记录还必须保存并返回对应脚本卡在聊天历史中的稳定 `scriptMessageId`。对已有脚本发起的普通 Run 复用该脚本
资源的规范消息锚点；首次受管工作流在最终脚本消息与 script resource 原子发布时，把锚点一次性写入 run；Retry 产生
新脚本时指向新的脚本消息。仍在生成首份脚本或生成失败且从未产生用户可见脚本的运行允许锚点为空，界面显示“脚本
尚未生成”，不能猜测最近一条脚本消息。锚点消息必须与 run 属于同一会话且类型为 script，跨用户和损坏引用不能
返回其他消息。

用户点击运行记录的主要内容区域时，前端定位到 `scriptMessageId` 对应的历史脚本卡。目标已加载时直接滚动；目标不在
当前聊天分页时，使用会话消息的 `aroundId` 读取目标前后连续上下文，并把聊天区切换到以目标为中心的历史窗口；最新
消息页继续缓存，SSE 新消息只增加“有新消息”状态，不插入当前历史窗口。界面显示“回到最新消息”，返回时恢复或重新
加载最新页。目标窗口渲染后滚动到卡片、移动无障碍焦点并短暂高亮。不得把不连续的旧上下文与最新页直接拼接，也
不得通过脚本名称、文本内容或列表位置猜测目标。窄屏下先关闭遮挡聊天的运行面板；定位失败时保留当前位置并显示诊断。
运行详情展开/收起和删除使用各自独立按钮，不能与主区域点击混在同一嵌套按钮中。

数据资源没有草稿、发布、激活和面向用户的版本历史。重新上传以及参数卡确认的 `para` 修改都通过 replacement 产生
新资源和新 artifact，再原子转移 alias，使界面中的当前 alias 表现为被覆盖；旧资源取得备用 alias 并标记“已被替换”，
作为独立资源继续可见，且已有运行或血缘继续引用其原 artifact。修改 display name 或 alias 只更新资源元数据，不改变
内容 hash。再次应用案例或重新导入模型也产生新的普通 `para` 资源；若同一会话已有当前 `para` alias，必须在确认卡中
让用户选择覆盖、另存或取消。

从普通数据资源项发起重新上传时，候选确认卡必须比较新旧 schema、row count、可识别的时间范围、内容 hash 和解析诊断，
即使 schema 完全相同也只有用户选择“确认替换”后才能转移 alias；schema 变化允许替换，但卡片必须突出列增删、
dtype/单位变化和已知兼容性影响，不能把上传动作本身视为替换确认。用户也可以选择“作为新资源保存”，此时新资源
使用另一个合法 alias 发布且不设置替换关系；用户取消则不发布新资源，并按暂存清理规则处理候选，旧资源和 alias
始终保持不变。

确认替换后，alias 转移必须在新资源完成格式、schema 和安全处理后原子提交，并记录 `replacesResourceId`、转移
前后 alias、差异摘要与时间。所有仍绑定旧 `resourceId` 或依赖转移前 alias 解析结果的未确认配置同时失效并要求
重新选择；已确认工作流和已创建运行继续使用其冻结资源，以后通过成功脚本“运行”创建的运行按当前 alias 解析到
新资源。普通上传、同名文件上传或仅创建失败记录都不得抢占现有 alias。

用户确认列映射或类型/单位转换后，服务端创建一份新的不可变规范化数据资源，不把转换仅保存为某次研究的临时
绑定，也不覆盖源资源。派生资源除普通资源元数据外，还必须记录 `sourceResourceId`、目标 `schemaRef`、受控映射
和转换 spec 及其 hash、执行时使用的 engine resource snapshot、转换诊断和内容 hash。源资源与派生资源都保留在
当前会话的数据文件列表中，用户可以分别查看、下载、选择和删除；artifact 内容可以按 hash 去重，但资源身份和
血缘不能合并。后续研究直接绑定派生资源，无需重复执行或重新确认同一转换。

仿真结果数据集和物化分析数据集默认只保留在各自的运行或分析历史中，不自动出现在“数据文件”，避免每次运行
污染可复用输入列表。用户通过自然语言明确要求“将该结果作为输入数据”或同等意图时，Agent 使用稳定 dataset ID
调用受控能力，在当前会话创建新的不可变数据资源并分配合法 alias；存在多个候选结果时必须先在对话中让用户选择，
不能按最近一次结果猜测。新资源复用已经验证的规范 Parquet artifact，记录来源 dataset、run 或 analysis ID、
来源 content hash、schema 和创建意图，不复制内容也不丢失血缘；按用户内容 hash 去重规则计费。该资源随后作为
普通数据资源与上传资源遵守相同的查看、下载、删除、重新上传、alias、兼容校验和研究绑定规则，
删除来源运行或分析时由资源引用保留
所需 artifact 与最小来源墓碑；下载能力按其没有上传原文件的来源类型只提供规范 Parquet。

## Run bindings and reproducibility

脚本创建或研究规划必须先查询当前门面声明的输入，再按需查询当前 active 模型表和当前会话可用的数据资源，不能把
模型表集合、辅助 alias 或 `para` 的资源 ID 写死在 Prompt 中。门面没有 `inputKind=model` 输入时不要求会话存在
active 模型，也不为该次研究伪造模型绑定。
配置确认阶段由 Agent 和前端用稳定资源 ID 选择资源，并使用服务端分配的 alias。生成的 RSS 只引用资源 alias，不
保存或接收 `resourceId`。用户点击“确认并生成脚本”
时，后端必须在同一个事务中重新校验配置草稿、门面实际要求的当前 active 模型（如有）、所选资源、普通数据 alias、
所有权、schema 兼容性
和 engine snapshot；任一内容已变化则返回 `configuration_stale` 并刷新
摘要，不得生成脚本。校验通过后，事务同时创建确认记录、受管工作流和首次执行输入快照，冻结门面实际使用的模型
版本（如有）、所选资源 ID 与内容 hash：

```json
{
  "alias": "load_forecast",
  "resourceId": "01K...",
  "contentHash": "sha256..."
}
```

通过参数卡读取 `para` 等 Struct 资源时，确认事务还必须校验当前 resource ID/hash、`schemaRef` 和规范字段值。字段
未修改时直接冻结当前资源；字段已修改时，最终摘要必须明确显示覆盖目标与差异，确认事务先以普通 replacement 语义
发布新的单行 Struct Parquet 资源并转移 alias，再把新 resource ID/hash 冻结为首次 workflow 输入。已有运行仍引用旧
artifact，参数覆盖不会改写历史。

首次生成、首次 tensoreval 执行和该工作流内的全部自动修正 attempt 都使用这份确认时冻结的输入快照构造私有输入
树。即使脚本生成期间用户删除资源、重新上传同名文件或激活新模型，该工作流也不切换到未经确认的内容；冻结引用
直到工作流终态后仍由运行历史持有。旧 artifact 只有在所有运行和派生血缘都不再引用时才能回收。

脚本本身仍不绑定某个资源版本。Agent 脚本首次执行使用上述确认快照；脚本成功后点击“运行”，后端才在按钮点击的
新事务中按门面声明重新读取所需的最新 active 模型（如有），并按脚本所需 alias 解析最新数据资源，校验通过后为
这次运行冻结新的输入快照，不继续绑定首次执行的模型或资源；因此 `para` 被修改或覆盖后再次“运行”会使用当前
alias 指向的最新内容。没有模型输入的门面可以只凭普通数据资源运行；运行审计中的模型版本字段为空而不是绑定一个
无关 active 模型。每次运行都保存实际使用的可空 model version ID/模型 content hash，以及资源 ID 与资源 content
hash，因此不同时间使用不同模型或数据资源得到的结果仍可
复现和比较。

## Engine documentation authority and study scope

V4 不从 zjudss 仓库内置研究类型、参数顺序或 DataFrame schema，也不在运行时扫描 `eig-rs/psa/src/dsa`
源码。生产配置 `SPARROWZZ_DIR` 必须直接指向当前可读的 `sparrowzz` 资源根目录；本次启动所使用的
`$SPARROWZZ_DIR/dss/docs` 是 RSS 语法、DSA 研究门面、函数签名、输入 DataFrame schema、结果合同和
Agent 引擎知识的权威来源。仓库中的相对路径和开发机上的 `../eig-rs` 只能用于开发验证，不能成为生产合同。

服务启动时读取并验证 `$SPARROWZZ_DIR/dss/docs/catalog` 及其引用的文档，按实际读取字节发布不可变 engine
resource snapshot。Agent、研究规划器、参数卡片、数据资源匹配、修正合同一致性检查和运行审计必须使用同一个 snapshot；
更新 `SPARROWZZ_DIR` 下的文档或 catalog 后必须重启服务，已创建的计划、脚本和运行继续保存其实际 snapshot
标识与合同引用。

engine resource snapshot 是按实际文档字节 hash 去重的系统级共享 artifact，不属于任何用户或会话，也不计入用户
artifact 数和字节配额。本次启动发布的当前 snapshot 必须保留；旧 snapshot 只要仍被已确认配置、脚本、工作流、
attempt、运行、结果或派生血缘引用，也必须连同其目录合同和必要文档保持可读且不可修改，供历史详情、诊断和审计
解释实际运行环境。旧 snapshot 不得重新进入新研究规划，也不能因为仍被历史引用而覆盖当前能力目录。

删除业务资源时在同一引用事务中释放 snapshot 引用；只有 snapshot 不是当前启动版本且最后一个业务引用已经释放，
系统 GC 才允许回收其 artifact。相同 hash 的多次启动复用同一个 snapshot 身份和内容，不能重复存储或因重启增加
引用泄漏。snapshot 存储故障、引用缺失或 hash 不一致属于系统完整性错误，不能降级为读取工作树当前文件来解释
旧运行。

服务发布新 engine resource snapshot 后，新研究规划必须按新 snapshot 重新校验当前 active 模型表和会话数据资源，
不能沿用旧 snapshot 的兼容结论。数据兼容状态按 `(resourceId, snapshotId, schemaRef)` 保存，因此同一资源可能对一个
门面兼容、对另一个门面需要映射；`needs_mapping` 是针对当前目标输入的状态，不得把资源全局标成不可用。需要
映射的资源仍可查看、下载和用于历史追溯，但不参与该输入的自动预选；用户通过受控映射卡确认后创建引用新 snapshot
和目标 schema 的派生资源，不能静默改写原资源。

门面声明的 active 模型表不符合新输入 schema 时，新规划以 `model_schema_incompatible` 指出表、列和 dtype 差异并停止，
只能通过模型导入或自然语言修改形成新草稿并发布新模型版本，不能就地改变 active 版本。历史计划、脚本、运行、
结果及其旧 snapshot 引用保持不变。已经存在的脚本再次“运行”仍按既定规则使用当前 tensoreval、门面所需的最新
active 模型（如有）和当前 alias 资源做一次执行，不因 catalog 升级自动改写或进入修正；运行失败时直接返回实际错误。

V4 支持该权威目录发布的全部 **DataFrame 研究门面函数**，不在 zjudss 中维护固定的五类研究枚举。目录新增
合规门面后，zjudss 应通过新 snapshot 发现它，而不是再修改一套函数名、参数顺序或 schema 硬编码。每个已发布
研究门面必须提供稳定函数 ID、RSS 函数名、用途、完整参数顺序、结果集合，并为每个参数提供
`inputKind = model | struct | data`、直接 `schemaRef`、必填/条件必填规则和行数约束；Struct schema 还必须提供
生成参数卡片所需的字段类型、单位、范围、默认值、枚举及字段联动，Data schema 必须足以校验上传资源兼容性。
各门面独立声明实际输入：引用完整配电网的门面把实际需要的网络表逐项声明为 `model`，只处理保护配合等独立数据的
门面可以没有任何 `model` 输入。zjudss 不得为了统一调用形式，给所有门面强制补齐 20 张网络表或 active 模型。

snapshot 为每个有效研究门面计算规范化 `facadeContractHash`，内容必须覆盖稳定门面 ID、RSS 函数名、参数顺序、
每个输入的 inputKind 与传递引用的完整 schema、Struct 字段约束、结果集合及组合约束；说明文字、排版或不影响执行
合同的文档修改不得改变该 hash。配置确认、修正合同、脚本和运行同时保存 snapshot ID 与该门面合同 hash，使服务
能够区分“文档版本变化”和“本次研究的可执行合同变化”。

目录校验按门面隔离。某个已发布门面缺少上述合同、引用不存在的 schema 或包含不一致的参数/结果定义时，服务
不得把它加入本次 snapshot 的可执行能力集，但也不得因此禁用其他合同完整的门面或阻止整个服务启动。服务必须
为被禁用门面保存结构化诊断，至少包含稳定函数 ID、RSS 函数名、稳定错误码、问题字段和可读原因，并在能力查询、
Agent 规划和聊天回复中保持一致。该诊断不要求新增独立的系统状态页面；Agent 不得为被禁用门面生成脚本，用户
在对话中提出对应研究时，应明确说明当前引擎文档合同无效及具体问题，而不是改用另一种研究、猜测输入或返回
笼统的“不支持”。

以下函数不属于 V4 研究规划范围：`import_dss*`、`import_bmopf*`、`ds_*_dss_plan*`、`ds_dss_*` 以及其他接收
文件路径或 URL 的导入/执行门面。模型和案例先通过 zjudss 导入流程形成模型工作区；研究脚本直接引用 active
模型表、参数卡片生成的单行 Struct DataFrame 和用户选定的数据资源，不重新导入模型文件，也不向 Agent 暴露
服务器路径或 URL。

## Study input collection and explicit confirmation

用户用自然语言提出研究需求后，Agent 先从当前 engine resource snapshot 选择对应的 DataFrame 研究门面，再按
该门面的输入合同收集全部信息。在研究函数、模型输入、Struct 参数、Data 资源绑定和结果选择全部明确以前，Agent
不得编写或保存 RSS 脚本。缺少模型输入时应指出缺少的模型表；缺少 Data 输入时，应让用户从当前会话已经上传的
兼容资源中选择，或者上传新文件。

同一自然语言需求可能对应多个有效门面时，Agent 必须在对话中展示候选研究选择卡片，由用户确定具体函数。卡片
不能只列函数名，还必须依据当前 engine resource snapshot 说明各候选项的适用场景、算法或研究目标差异、额外输入
要求、能力与限制以及结果差异，使用户能够理解选择的影响。目录必须为同一研究族提供稳定分组和上述可解释元数据；
缺少必要说明的门面不能进入候选卡片。Agent 可以结合当前模型事实和用户已经表达的目标标出推荐项并说明理由，
但不得把推测写成引擎事实，也不得用推荐项替代用户选择。

用户已经明确指定算法、研究方法或稳定 `ds_*` 函数名，并且它能唯一映射到一个有效门面时，Agent 直接采用该门面，
不再展示候选选择卡片。显式指定的 Newton、Radial、WLS、MNMR、MCE 等选择不得因模型拓扑或默认推荐而被降级、
改写或替换；如果所选门面当前不可用，应在对话中返回该门面的具体诊断。跳过候选卡片不等于跳过输入收集、参数
卡片、结果选择或最终配置确认，所选门面仍须出现在最终摘要中。

输入合同中 `inputKind=struct` 的 DataFrame 表示一组结构化参数，使用由 schema 动态生成的参数输入卡片收集，
不得要求用户通过自然语言拼写字段和值。卡片负责类型、必填项、单位、范围、枚举和字段联动校验，并生成符合合同的
单行 DataFrame。卡片从 schema 兼容的普通数据资源读取初值；如果 active 模型与某个 `para` 资源来自同一 import/case
且只有一个兼容资源，自动预填并在卡片中明确显示来源，用户可以恢复目录默认值、改值或改选其他资源。存在多个合理
资源且没有唯一同源项时必须让用户选择，不能按最新时间猜测。参数卡修改后的确认会覆盖所选普通资源，或者在用户
选择“另存”时创建新的普通资源。`inputKind=data` 的 DataFrame 表示数据集或序列，同样绑定普通数据资源，但通过资源
选择和列映射处理，不用参数卡片逐项填写。门面声明的模型输入只从本次 active 模型的实际网络表清单中解析，不能
按固定数量给函数补参；门面没有模型输入时不要求 active 模型。`para` 不得作为 active 模型表出现。

没有兼容 Struct 资源时，参数卡使用目录默认值并要求用户补齐所有缺失必填字段；最终确认必须创建一个新的普通单行
Data 资源并分配 alias，随后再冻结它并启动工作流。参数卡字段更新只修改配置草稿，不能在最终确认前覆盖资源。

某个 Data 输入存在多个 schema 兼容的当前会话资源时，Agent 必须在对话中展示资源选择卡片，由用户确定实际
绑定。卡片至少显示 `displayName`、alias、schema 摘要、行数以及 schema 能够识别的时间范围；还应显示来源文件、
工作表和创建时间等已有元数据，帮助用户区分内容。兼容性由门面的 `schemaRef` 和服务端验证结果决定，Agent 不得
仅根据文件名、alias 或自然语言相似度把资源判定为兼容。用户选择后在配置草稿中保存稳定 `resourceId`，alias 用于
生成脚本变量；`resourceId` 不写入 RSS。最终确认前如果资源被删除、替换或校验状态变化，原选择失效并要求重新选择。

某个 Data 输入只有一个 schema 兼容的当前会话资源时，系统自动预选该资源，不额外要求用户完成一次资源选择。
自动预选必须在最终配置摘要中清楚显示，用户可以在确认前取消、更换资源或上传新资源；自动预选本身不构成用户
确认，也不能触发脚本生成。没有兼容资源时不进行猜测，输入保持缺失并在对话中提供上传入口。

上传 DataFrame 的列名或 dtype 与目标 `schemaRef` 不完全一致，但服务端能够根据列名、类型和目录声明的别名与
转换规则可靠推断时，应在对话中展示列映射和类型转换卡片。卡片逐项显示源列、目标字段、源/目标 dtype、单位
换算、必填字段状态、可能的数据损失以及有界样例和校验诊断，用户确认后映射才生效。用户可以修正预填映射；
无法可靠推断、存在多个同等候选、缺少必填列或需要目录未声明的转换时，不得自动绑定，必须要求用户选择或修正。
Agent 不能提交 SQL、任意表达式或任意脚本作为转换规则，服务端也不能静默丢列、截断值、填充必填数据或改变单位。

同一会话再次提出同一种研究需求时，Agent 应询问是否沿用上一次已确认的参数；这里的“参数”专指该 `ds_*`
研究门面的最后一个 `para` 输入，不包括其他 Struct 输入，也不自动复用上一次上传文件或 Data 资源绑定。用户
选择沿用后仍须在最终确认中看到复用值及来源，并可在生成脚本前修改。用户不沿用时，参数卡再按当前兼容 `para`
资源或目录默认值初始化；历史参数复用和当前资源是两个明确来源，不能静默相互覆盖。任何字段修改都必须在最终摘要
中显示将覆盖或另存的资源及差异。

用户通过自然语言要求修改已有研究的参数时，Agent 读取该研究上一次已确认配置，并打开预填的 `para` 参数卡片；
用户在卡片中修改和校验，不能通过 Agent 直接改写已经成功的脚本。除非用户同时要求调整，研究门面、其他 Struct
输入、所需 Data alias 和结果选择从被引用配置预填；门面所需的 active 模型（如有）和 alias 对应的数据资源在最终
确认事务中取最新值并冻结为该新工作流的首次执行输入。
用户检查完整摘要并再次确认后，系统创建一个新的 Agent 脚本和受管执行工作流，立即执行并适用首次执行的自动
修正规则。

参数修改的来源可以由用户点击的脚本/运行/结果卡片、明确引用的对话对象或唯一匹配的当前研究上下文确定；来源
唯一时直接打开对应预填卡片。存在两个及以上合理候选时，必须在对话中展示已有仿真配置选择卡片，显示函数、时间、
主要参数、模型版本和运行状态，由用户选择基准。Agent 不得仅因某项时间最近就猜测来源；最终确认摘要必须显示
被引用的基准研究。

新工作流必须保存 `derivedFromWorkflowId`、来源运行 ID、结构化参数差异和结果选择差异；旧脚本、旧运行和旧结果
保持不变。新运行成功后不自动创建比较或派生数据；用户用自然语言说明要比较的指标、范围或展示方式后，Agent 再
通过比较能力按两个稳定 run ID 分析修改前后结果，不能只按“上一次”在后台猜测来源。比较产生的表格、图表数据
和物化结果继续作为独立不可变资源保存，并记录两个来源运行。

门面提供多个结果 DataFrame 时，生成脚本前必须展示结果选择卡片，让用户明确选择本次需要物化和保存的结果。
卡片的候选项、稳定结果 ID、名称、说明和约束全部来自当前 engine resource snapshot；Agent 和前端不得自行维护
结果名枚举。目录必须为门面声明合法的推荐结果集合；结果选择卡片首次显示时默认勾选该集合，用户可以直接接受，
也可以在最终确认前调整。推荐集合不存在、引用未知结果或违反结果组合约束时，按门面合同无效处理，不允许 Agent
或前端自行猜测默认结果。结果选择与函数、模型版本、Struct 参数和 Data 资源绑定共同组成一份完整配置摘要。
只有用户对该摘要执行显式“确认并生成脚本”操作后，服务端才能签发计划并允许 Agent 生成 RSS；自然语言中的模糊
肯定不能替代该确认操作。确认事务提交前发生的输入变化会使配置失效并要求刷新摘要；提交成功后首次工作流使用
事务中冻结的输入，不受随后模型激活、资源重新上传、重命名或删除影响。

## Managed execution and automatic script repair

用户确认完整研究配置后，后台生成一个受管脚本并立即创建首次执行工作流，不需要再点击脚本卡片。首次执行成功时，
同一轮对话直接返回最终脚本和结果入口。失败时后台自动修正并重试；执行前不运行 zjudss 静态校验器，脚本语法、
函数参数和运行可行性均以实际 tensoreval 进程结果为准。所有进程调用仍必须经过 `backend/src/adapters/`，并显式使用私有
`--result-dir` 和 `--output-format parquet`，服务器路径不进入浏览器或普通 Agent 工具参数。

首次执行成功后，脚本卡片保留名称为“运行”的按钮；这里的“运行”明确表示使用已经成功的最终脚本再次创建一次
仿真运行，按门面需要绑定点击时最新的 active 模型（如有）和数据资源，并产生一组新的运行记录和结果，不是首次
执行入口。再次
“运行”只调用一次 tensoreval：成功时返回新结果，失败时直接返回脱敏错误信息，不进入自动修正循环，也不改变
已经成功的脚本内容。首次执行或后续自动修正达到上限仍失败时，保留同一 Agent 脚本的最后候选内容和诊断，按钮
改为“重新尝试”；用户点击后从该候选内容启动一个新的执行工作流，并重新获得完整的修正次数预算。

“重新尝试”创建工作流前必须比较门面所需的当前 active 模型（如有）及脚本所需 alias 的当前资源绑定与上一个失败
工作流的冻结输入。模型版本（如有）、资源 ID 和内容 hash 都未变化时，可以直接复用原冻结输入启动新工作流；存在
变化时，对话先显示受控的
输入差异确认卡，逐项列出旧/新模型版本、资源名称、alias、schema 摘要和内容 hash。只有用户明确确认后，事务才
冻结当前最新输入并启动新的完整修正预算；取消或关闭卡片不创建工作流。新工作流保存来源 workflow ID 和结构化
输入差异，研究函数、算法、Struct 参数、输入 alias 与结果集合仍受原修正合同约束。

当前所需 alias 已不存在、处于 `needs_rename`、归属错误或新资源 schema 不兼容时，“重新尝试”保持阻塞并显示具体
诊断，不能用其他资源静默代替，也不能调用修正模型或 tensoreval。若上次失败发生在首次脚本尚未生成之前，同样先
完成输入差异检查，再从确认配置重新生成脚本。这样重新上传修正数据或激活新模型后可以显式采用新输入，而普通
脚本错误的原输入重试无需重复确认。

“重新尝试”还必须比较原修正合同与当前 engine snapshot 中同一稳定门面的 `facadeContractHash`，但不比较整个
snapshot hash 或 tensoreval binary hash。门面合同 hash 相同，即使其他门面或说明文档已经变化，也可以在当前
snapshot 下继续使用最后候选和原研究配置；新工作流同时记录原 snapshot、当前 snapshot 和相同合同 hash。当前
门面不存在或合同 hash 不同时，返回稳定 `study_contract_changed`，展示函数签名、输入 schema、参数或结果合同的
结构化差异，保留旧候选和历史，但不调用修正模型或 tensoreval；用户必须按当前 snapshot 重新规划、检查完整配置
并生成新的 Agent 脚本。成功脚本普通“运行”和手写脚本执行仍直接调用当前可用的 tensoreval，不做 binary 版本
拦截，也不因 snapshot 整体 hash 变化而拒绝。

每次 tensoreval 执行都捕获进程退出码和 stderr。受管研究脚本在用户最终确认时冻结独立的结果合同，包含所选结果
稳定名称、顺序无关的精确集合、每个结果的完整 schema、组合约束、来源 snapshot 和 `facadeContractHash`；该合同
随最终脚本保存，不能在后续运行时替换成当前目录的新定义。受管工作流成功必须同时满足：退出码为 0；实际结果
DataFrame 的稳定名称集合与脚本冻结集合完全一致；每个结果都可作为 Parquet 读取且符合脚本冻结 schema。零行结果
只要保留合法 schema 就是有效结果；结果缺失、重复、额外、Parquet 损坏或 schema 不匹配均使用稳定
`result_contract_invalid` 失败，诊断列出 expected/actual/difference，任何部分或额外结果都不得发布。

首次执行和自动修正使用确认时冻结的结果合同。成功脚本以后点击“运行”仍实际调用当前可用的 tensoreval，但结果
继续按该脚本的冻结合同校验；当前引擎合同或输出已经变化时直接返回 `result_contract_invalid`，不自动修正，也不
用新 schema 重新解释或发布旧脚本结果。成功时服务保存最终脚本、全部规范结果 DataFrame、运行快照和审计信息，
并在对话中返回脚本及最终结果入口。

所有受管和手写脚本共享结果安全上限：`.env` 的 `RESULT_MAX_FILES=100`、
`RESULT_MAX_FILE_BYTES=536870912`（512 MiB）和 `RESULT_MAX_TOTAL_BYTES=2147483648`（2 GiB）。后端启动时必须
校验三项为正数且总量不小于单文件上限。tensoreval 退出后先在私有 result-dir 中检查文件数量、每个文件大小、
累计大小、普通文件/路径边界、Parquet 可读性和压缩，再检查受管脚本的精确结果合同，最后才在用户配额事务中发布；
任何阶段失败都清理整个未发布目录，不能先提交一部分结果。

adapter 还必须在 tensoreval 运行期间持续监控该次私有 result-dir，不能只在进程退出后检查。发现目录项数量、任一
普通文件大小或累计字节超过上述上限，或者出现符号链接、目录外逃逸和其他禁止项时，立即终止整个进程组、停止
当前引擎执行、清理未发布目录，并返回对应结果限制或路径安全错误；首次受管执行是否进入下一轮仍按既定自动修正
规则处理。监控读取必须有界且不能跟随符号链接；监控器
自身失败时以 `result_monitor_failed` 终止运行，不能在失去限制保护后继续等待引擎。由于终止和文件写入存在竞态，
进程退出后仍必须执行一次最终严格扫描，运行期监控不能替代最终合同校验。

文件数、单文件或总量超限分别返回稳定 `result_file_limit`、`result_file_too_large`、`result_total_too_large`，并记录
实际值和配置上限，但浏览器不接收服务器路径。首次受管执行或“重新尝试”可按既定自动修正规则处理这些结构化
结果诊断；成功脚本普通“运行”和手写脚本执行直接失败。安全上限校验失败不创建 artifact、不增加用户正式配额，
配额不足则在结果全部通过安全和合同校验后以 `storage_quota_exceeded` 原子失败。

在首次执行或“重新尝试”的自动修正工作流中，非 0 退出码、`result_contract_invalid`、`result_file_limit`、
`result_file_too_large` 或 `result_total_too_large` 进入下一次修正；普通“运行”和手写脚本的单次执行则直接失败。
`result_monitor_failed`、`engine_timeout` 和其他基础设施错误或无法通过修改脚本纠正的路径安全错误直接终止工作流，
不进入修正。修正 prompt 必须包含当前脚本全文、该次 tensoreval 的脱敏 stderr（允许为空）、可选的结构化结果
合同诊断，以及精确指令“只输出修改后的完整脚本，不要解释”。
用户最终确认的研究配置同时形成不可变的修正合同，至少锁定 engine resource snapshot、研究门面稳定 ID 与 RSS
函数名、算法选择、模型输入和 Data 输入 alias、全部 Struct 参数规范值以及结果集合。每轮修正 prompt 都必须包含
这份合同，并明确要求只修正 RSS 语法、表达式、列引用、参数装配和同一函数的调用方式；修正模型不得更换研究
函数或算法，不得添加、删除、替换输入 alias，不得修改 Struct 参数值或增删结果。自动修正不能成为绕过用户最终
确认、把 Newton 改成 Radial 或用其他数据代替已选输入的入口。

该边界不能只依赖自然语言提示。后台必须把初始生成和每次修正得到的候选脚本与不可变修正合同做结构一致性检查；不检查一般 RSS 语法
和运行可行性，这两项仍完全以 tensoreval 为准。候选脚本违反锁定配置时，不得作为成功脚本发布或以其结果满足
当前工作流，并使用稳定诊断 `repair_contract_violated` 指明被改变的合同字段。具体受控脚本表示、解析或组装方式在
详细实施方案中确定，但不能用字符串包含判断代替结构检查。

初始生成候选不消耗 `SCRIPT_REPAIR_MAX_ATTEMPTS`；若它违反合同，则保存并直接以该诊断请求第一次修正。此后修正
模型每返回一份候选完整脚本就消耗一次预算，无论该候选是否通过修正合同检查。修正阶段的
`repair_contract_violated` 候选仍须作为不可变 attempt 保存脚本 artifact/hash 和结构化违规字段，但不得启动
tensoreval，也不产生结果目录；预算尚未耗尽时，把该诊断与锁定合同一起放入下一轮修正 prompt。预算耗尽时工作流
直接以最后一次合同违规诊断进入失败终态，不额外调用模型或引擎。这样模型反复改变研究目标不会形成无限重试，
进度卡的 attempt 序号也与实际模型修正次数一致。

发送给外部模型前只替换服务器绝对路径、secret 和其他敏感值，必须保留行号、函数名、错误类型、参数和其他修正
脚本所需的诊断上下文；替换位置使用明确占位符，不能把删减后的内容伪装成原始 stderr。模型回复只能作为下一份
候选完整脚本并直接进入下一次 tensoreval 执行，不能作为说明文字解释，也不能被视为成功结果。语法错误与其他
脚本错误一样，以非零退出码和 stderr 驱动下一轮修正。

修正模型、对话和普通 API 使用的脱敏 stderr 还必须受后端 `.env` 的 `SCRIPT_REPAIR_STDERR_MAX_BYTES` 限制，
默认值为 65536（64 KiB）。超限时按 UTF-8 字符边界保留开头和结尾两段，并在中间加入明确截断标记及被省略的
字节数，不能只保留开头而丢失通常位于末尾的根因；脱敏和敏感信息替换在截取前完成，避免截断改变敏感值识别。
每个 attempt 保存截断前脱敏内容的 hash、实际发送内容的 hash、原始/发送字节数和是否截断，便于证明修正模型
实际看到了什么。该限制不改变后端受限审计对原始 stderr 的独立有界保存，原始内容和其容量上限均不得暴露给
外部模型、浏览器或普通 API。

tensoreval 进程的 stdout 和 stderr 不能先由 `command.output()` 一类接口无界读入内存再做上述截断。adapter 必须
并发、持续排空两个管道，并通过 `.env` 的 `ENGINE_PROCESS_OUTPUT_MAX_BYTES` 对每个流分别做有界捕获，默认值为
1048576（1 MiB）。超过上限后继续读取并丢弃未保留部分，避免子进程因管道写满阻塞；内存中只保留首尾字节段和
明确截断元数据。读取过程中流式计算完整字节流 hash 和总字节数，attempt 审计同时保存保留内容 hash、完整流 hash、
总字节数和截断状态。非 UTF-8 内容在保留原始有界字节审计的同时，以显式替换字符生成可见诊断，不能导致服务
崩溃。该进程层截断本身不改变退出码或成功判定，实际结果仍由退出状态和结果合同决定；外部模型、对话和普通 API
只能看到进一步脱敏并受 64 KiB 上限约束的 stderr。

修正上限通过后端 `.env` 的 `SCRIPT_REPAIR_MAX_ATTEMPTS` 配置，默认值为 3。该值表示初始执行失败后最多允许的
模型修正次数，初始执行不计入，因此默认最多执行 4 次 tensoreval。达到上限仍未成功时，工作流进入失败终态，
在对话中返回最后一次失败原因和有界的尝试摘要，不继续后台重试。

Agent 首次生成脚本和后续修正调用外部模型时，传输层失败使用独立的 `.env` 配置
`AGENT_MODEL_RETRY_MAX`，默认值为 2，表示原请求失败后最多再重试两次。网络超时、限流和服务端错误采用带抖动的
短暂退避；服务提供 `Retry-After` 时在后端允许的等待上限内遵循该值。传输重试不产生候选脚本，也不占用
`SCRIPT_REPAIR_MAX_ATTEMPTS`，但每次请求的阶段、序号、耗时和脱敏错误必须进入受限审计；用户取消工作流后立即
停止等待和后续请求。重试耗尽时，首次生成阶段以 `script_generation_model_unavailable` 失败，修正阶段以
`repair_model_unavailable` 失败，保留已经存在的最后候选脚本和 attempt 历史并显示“重新尝试”，不能把提供方错误
伪装成脚本错误或继续调用 tensoreval。

单次 tensoreval 执行继续受后端 `.env` 的 `TENSOREVAL_TIMEOUT_MS` 限制，默认 120000 毫秒。无论发生在初始执行、
修正后的执行、成功脚本再次“运行”还是手写脚本执行，超时都必须终止整个 tensoreval 进程组、清理该次未发布的
结果目录并保存实际耗时和结构化 `engine_timeout` 诊断，任何已写出的部分结果都不得发布。超时不进入自动修正，
也不继续消耗剩余修正次数；受管工作流直接进入失败终态并显示“重新尝试”，单次运行则直接返回超时错误。已经在
超时前完成的模型修正仍按实际发生计入预算和审计。

每轮都必须持久保存中间状态，至少包括工作流 ID、attempt 序号、父 attempt、候选脚本 artifact/hash、执行状态、
退出码、stderr 诊断、结果 artifact（如有）、Agent bundle/skill/model 引用、engine resource snapshot 和时间戳。
这些 attempt 都属于同一个 Agent 生成脚本和同一次运行工作流，不创建多个面向用户的“原脚本”“修正脚本”资源。
每个 attempt 的脚本 artifact 创建后不可修改，下一轮通过新 artifact 和父子血缘表达；受管脚本在工作流终态时
一次性确定其最终内容。成功时最后一次 attempt 就是用户看到并可再次运行的最终脚本，失败耗尽时则显示最后一次
候选脚本及失败诊断。历史 attempt 只在该脚本/运行的排查详情中展示，不进入普通脚本列表。这样既保持单一的用户
脚本概念，也不改写任何已经发布的 attempt artifact。一次显式“重新尝试”会创建新的派生工作流；它到达终态并产生
候选脚本后发布新的 Agent 脚本资源和脚本消息，并记录来源脚本/工作流，原失败脚本保持不可变。新运行锚定新脚本
消息，旧运行仍锚定旧脚本消息。原始有界 stderr 只保存在后端受限审计中，不进入 LLM、
浏览器或普通 API；修正 prompt、对话和用户可见的 attempt 详情统一使用同一份脱敏 stderr，并分别保存两者的
hash 以便审计对应关系。

自动修正只适用于用户完成 V4 研究配置确认后由 Agent 生成脚本的首次执行，以及失败脚本的显式“重新尝试”。
已经成功的 Agent 脚本再次“运行”不进入修正循环。用户手写、粘贴或上传的 `.rss` 同样不进入修正循环，服务不得
把其全文发送给修正模型，也不得自动改写用户内容。手写脚本每次执行只调用一次 tensoreval：
退出码为 0 后使用开放结果合同检查私有 result-dir，不预设结果名称或 schema，但必须至少包含一个名称合法且唯一、
可读、使用 Snappy 压缩并满足输出限制的 Parquet 数据集。所有实际名称、schema、行列数、大小和 hash 随本次运行
冻结；同一手写脚本下次运行可以产生不同集合和 schema，不用上次结果反向约束。

result-dir 没有任何数据集时返回稳定 `no_result_dataset`；存在重复/非法名称、非普通文件、非 Parquet、损坏文件、
错误压缩或任一大小/数量超限时，整次运行失败并清理未发布结果，不能发布其中合法的部分。非 0 退出码直接返回
脱敏 stderr 和失败状态；这些失败均不进入自动修正，原始 stderr 仍按相同规则进入后端受限审计。上传、粘贴或保存
手写脚本本身不得触发执行；脚本卡片提供明确的“运行”按钮，只有用户点击后才创建一次单次执行。用户可以只保存、
查看或稍后运行手写脚本，重复上传也不会产生隐式运行。

## Frontend behavior

右侧工作台新增与“模型工作区”“运行记录”并列的“数据文件”入口。它按当前会话持久展示普通数据资源，而不是只显示
本次页面生命周期内的上传队列。每项至少显示名称、alias、schema 摘要、行数、列数、大小、来源、创建时间和处理状态；
`para` 与其他资源显示方式一致，可以附加显示其 `schemaRef` 和来源模型/案例，但不形成独立资源类型。所有资源都提供
固定的查看、下载和删除操作；
上传、查看、下载和删除属于高频无歧义操作，可以使用按钮。删除按钮必须打开上述资源影响确认框，不能在第一次
点击时直接删除。

表格查看复用受控列投影、cursor 分页和 Parquet 下载能力。普通数据重新上传复用普通上传处理流水线并创建新资源。
改变 alias、
选择某个资源参与仿真、把它绑定为负荷预测或其他业务输入，优先通过自然语言进入 Agent 工具链；发生歧义时由
Agent 在对话中要求用户确认。

数据资源项提供固定“重新上传”入口并携带被替换资源的稳定 ID。新资源处理期间旧资源继续可用；成功后界面
原子刷新 alias 所有者，新资源取得旧 alias，旧资源保留并显示其备用 alias 与“已被替换”来源信息。候选卡必须
显示新旧差异，并提供“确认替换”“作为新资源保存”和“取消”；普通上传入口不执行 alias 转移。`para` 也使用同一
replacement 语义；参数卡修改 `para` 时，最终配置摘要复用差异卡并明确“覆盖当前资源”或“另存为新资源”。
当前 engine snapshot 能把任一普通单行资源匹配到 Struct schema 时，资源详情提供固定“修改参数”入口并打开 schema
驱动的参数卡；匹配不唯一时先选择目标 Struct schema，无法匹配时不显示该入口。

刷新页面、切换会话或服务重启后，未删除的数据资源仍能从服务端列表恢复。上传处理失败必须保留可读诊断；未完成
处理的记录必须在启动恢复中收敛为明确失败态，不能永久显示处理中。

受管脚本首次执行和“重新尝试”期间，对话中使用一个持久的进度卡实时更新状态，不为每个 attempt 追加一组展开的
工具消息。卡片默认只显示当前阶段（生成脚本、执行、修正、再次执行、成功或失败）、当前执行序号、修正序号及其
服务端返回的配置上限和已用时间，使用户能够判断后台仍在工作。界面不得把默认的 3 次修正/4 次执行写死；合同
违规的修正 attempt 会消耗修正次数但不增加执行次数。每轮 attempt 的时间、脚本摘要/hash、退出码和脱敏 stderr
默认折叠，用户
主动展开后查看；原始 stderr 永不进入该卡片。成功终态展示最终脚本和结果入口，失败终态展示最后原因、“重新尝试”
按钮和可展开的历次摘要。

成功终态只显示本次运行的结果数据集列表，不自动打开任何数据表、图表或分析。列表至少显示稳定 dataset ID、结果
名称、schema 摘要、行列数和大小，并提供固定“查看”和“下载”操作；即使只有一个结果也不自动展开。“查看”读取
原始结果表，用户需要筛选、汇总、绘图、解释或比较时继续通过自然语言交给 Agent，Agent 再创建独立分析、视图或
比较资源。

运行记录的“删除”按钮位于每条终态记录的操作区，不放在结果数据集逐项菜单中，也不要求用户用自然语言表达。按钮
必须先加载服务端影响预览再打开确认框；删除进行中禁用重复提交，成功后从列表移除整条记录。失败、取消和重启终态
即使没有结果也可以删除；queued/running 记录不显示可执行删除操作。逐张“删除结果”能力继续保留，用户可以选择只
删除某一结果或删除整条运行及其全部结果。

运行记录主区域显示“定位到脚本”的可理解提示并执行上述聊天跳转；原来的展开行为移到独立“展开详情/收起详情”
按钮。无 `scriptMessageId` 时主区域不可执行定位，但详情和终态删除仍可使用。定位成功后脚本卡获得程序化焦点，屏幕
阅读器播报“已定位到对应脚本”；高亮不能成为识别位置的唯一方式，并遵守 reduced-motion 偏好。

非终态进度卡提供固定“取消”按钮。取消请求必须幂等地把工作流收敛为 `cancelled_by_user`，停止排队中的步骤、阻止
创建后续 attempt，并尽力取消当前外部模型请求或终止当前 tensoreval 进程组。已经持久化的脚本和 attempt 历史
继续保留，未提交的私有结果目录被清理，不把部分输出发布为成功结果。取消与成功提交并发时以第一个完成的原子终态
转换为准，不能同时产生成功和取消消息。取消终态显示已有进度与“重新尝试”，再次尝试从最后候选脚本开始并获得
新的完整修正预算。

生成、执行和修正是归属会话的服务端持久工作流，不依赖发起请求的浏览器连接存活。刷新页面、关闭页面或切换到
其他会话均不取消后台工作；用户返回原会话后，通过工作流状态查询和 SSE 事件回放恢复同一张进度卡及已完成的
attempt。重连、重复拉取或 `Last-Event-ID` 回放不能重复创建 tensoreval 进程、重复调用修正模型或重置修正预算；
终态消息和结果也必须幂等落库，避免刷新产生重复脚本或运行记录。

同一会话最多存在一个非终态受管工作流，包括脚本生成、首次执行、自动修正和“重新尝试”。并发请求必须通过数据库
约束和事务原子拒绝第二个工作流，不能只依赖前端禁用按钮；错误响应使用稳定 `workflow_in_progress` 并返回当前
工作流的稳定 ID，前端定位已有进度卡并提示用户等待或取消。第二个研究请求不保存为待执行队列，也不在当前工作流
结束后自动开始；用户届时重新发起或确认，以便重新校验模型、数据资源和 engine resource snapshot。该限制不阻止
用户查看模型、数据文件、聊天历史、运行历史和已有结果；不同会话仍受全局和每用户的 Agent/引擎并发队列限制。

后端服务重启不自动恢复正在生成、执行或修正的进程。启动恢复把所有非终态工作流及其当前 attempt 确定性收敛为
`service_restarted` 失败，清理未提交的私有结果目录，保留已经持久化的配置、候选脚本、stderr 和 attempt 历史，
并在对话进度卡显示重启诊断与“重新尝试”。用户点击后，从最后已持久化候选脚本继续；如果重启发生在首份脚本
持久化之前，则从已确认配置重新生成。新的工作流获得完整修正预算，服务不得根据临时文件或不确定的外部模型调用
结果自动续跑。

## API and agent requirements

V4 API 至少提供会话数据资源的上传、列表、详情、分页行读取、下载和删除能力，以及受控 alias 更新能力。Struct-compatible
普通资源的参数卡修改必须先创建只读差异预览，再用短期 token 确认覆盖或另存；预览期间资源 hash 已变化时返回稳定
`resource_stale`，不得覆盖新内容。
运行删除提供影响预览和带 token 的确认删除接口，只接受稳定 run ID，不接受结果路径或客户端提供的结果 ID 集合。
运行列表 DTO 返回可空 `scriptMessageId`；会话消息分页的 `aroundId` 模式必须验证目标消息归属并确保响应包含目标，
供前端按 ID 定位，不新增按脚本名称搜索的旁路接口。
具体路由和 DTO 在实施方案中确定，并同步公共合同、功能目录和行为测试。数据资源、研究配置、运行和 Agent 工具
接口不得接受服务器路径、SQL、任意 RSS 修正表达式或任意 ECharts option；既有的专用手写/粘贴/上传 `.rss` 脚本
入口仍可接收用户脚本文本，并继续受 UTF-8、大小、所有权和单次执行边界约束。

Agent 至少具备以下受控能力：列出数据资源、读取元数据和有界行、更新普通数据 alias、把指定结果或物化分析 dataset 提升
为数据资源，以及在研究计划/脚本资源中声明所需资源绑定。提升操作只接受当前用户、当前会话可见的稳定 dataset ID
和受控名称，不接受路径或任意脚本。Agent 不直接删除资源，也不能在用户显式确认最终配置之前生成或执行受管脚本；
用户的最终确认同时授权首次生成和执行工作流。首次工作流结束后，只有脚本卡片的“运行”或“重新尝试”按钮可以
再次触发执行；执行失败后的修正循环由后端继续编排，不需要用户逐轮确认。

## Acceptance requirements

- 上传负荷预测 CSV、Excel 或 Parquet 后，它出现在“数据文件”中，不进入模型草稿或模型版本。
- 案例库或 DSS/bundle 静态导入产生的 21 张表必须拆成 20 张网络模型表和 1 个普通 `para` 数据资源；模型草稿、版本、
  active 表清单和模型表下载中都不得出现 `para`，数据文件中也不得把它显示成独立的“参数预设”类型。
- `para` 具有普通资源 ID、alias、schema、查看、下载、删除、重新上传和 replacement 能力；兼容 Struct 输入时通过参数
  卡读取和修改，确认覆盖会发布新 artifact 并转移 alias，不改写历史运行引用的内容。
- 任一普通单行资源匹配当前 Struct schema 时都能用参数卡修改；没有兼容资源时，完整填写参数并最终确认会创建新的
  普通资源，参数卡编辑过程中不得提前覆盖资源。
- 首次生成和修正冻结确认时的 `para` resource ID/hash；成功脚本再次“运行”按 alias 读取最新 `para`，每次运行继续
  冻结实际 resource ID/hash，保证覆盖前后的历史结果都可复现。
- 删除单个资源前显示名称、资源类型、可选 alias、大小和引用影响并要求确认；删除使未确认配置失效，但不取消已冻结工作流，
  也不破坏已有运行、结果和派生历史。
- 原始 CSV、Excel 或 Parquet 作为来源 artifact 长期保留并计入配额；用户可以分别下载原文件和规范 Parquet，
  Excel 多工作表共享原文件且最后一个资源或历史引用释放前不得回收。
- 从普通数据资源项重新上传时显示新旧 schema、行数、时间范围和内容差异；用户确认替换后新资源才原子取得旧 alias，
  也可另存为新资源或取消，失败和取消时旧资源及 alias 不变。
- 仿真结果和物化分析结果默认不进入数据文件；用户通过自然语言指定稳定 dataset 后可以将其提升为数据资源，
  复用规范 Parquet、保存来源血缘并按普通数据资源参与后续研究。
- 页面刷新和服务重启后资源列表仍可恢复。
- 删除会话前必须确认并展示模型、数据资源、脚本、运行、结果数量和空间影响；确认后立即隐藏会话、取消工作流并
  释放无引用 artifact，其他会话血缘仍需要的内容延迟回收。
- 每条终态运行记录显示“删除”；确认框展示结果数量、空间和派生引用影响，确认后运行及其全部直接结果同时从普通读取
  隐藏。非终态运行或存在 busy 结果时整次拒绝，已完成派生、比较、视图和提升资源继续可读并显示来源墓碑。
- 运行记录主区域能定位到同一会话中精确的脚本消息；未加载的历史页通过 `aroundId` 切换到连续历史窗口，随后滚动、
  聚焦和高亮脚本卡，并提供“回到最新消息”，不能把存在缺口的消息伪装成连续记录。详情展开与
  删除使用独立按钮，无脚本锚点时明确显示尚未生成且不猜测其他消息。
- 每个用户默认配额为 20,000 个不同内容 artifact 和 20 GiB，80% 告警且不按时间自动删除；达到硬限制后拒绝新
  内容并保持已有历史可读，多个运行结果不得部分发布。
- 上传默认限制为单文件 50 MiB、单批次 500 MiB、压缩包 1000 项/解压 2 GiB/压缩比 100；任一限制超出时整次
  拒绝且不留下部分资源。
- CSV/Parquet 一文件一候选，Excel 按非空工作表形成候选；可见表默认全选、隐藏表默认不选，用户确认后所选资源
  原子发布，任一候选失败时不得发布部分批次。
- 同批上传可逐候选确认“模型表/数据资源/不导入”；确认后拆成模型与资源两个独立事务，各自内部原子并分别报告，
  不得静默分类或用一方失败回滚另一方成功内容。adapter 静态导入明确产出的 `para` 固定显示为“数据资源/不导入”，
  进入资源事务且不能改成模型表；发布后与其他普通资源使用相同能力。
- 文件解析设置存在歧义时显示受控卡片确认分隔符、编码、表头、数字/日期/时区和 Excel 范围；不得使用服务器默认
  值静默猜测，也不得把该卡片视为研究 Struct 参数卡片。
- 未确认候选默认保留 24 小时并预留用户字节配额；刷新和重启后可以恢复，放弃或过期后清理暂存并释放预留，
  过期批次以 `upload_batch_expired` 拒绝继续确认。
- Excel 公式、宏和外部链接不得执行；只读取已有公式缓存值，必填值缺少缓存时以
  `excel_formula_value_missing` 拒绝候选，非必填值转为 null 并显示诊断。
- Agent 能根据自然语言找到资源并生成使用其 alias 的脚本；歧义时先询问，不猜测资源。
- 用户可在选择研究门面前上传通用数据资源；上传不要求匹配当前 catalog schema，参与具体受管研究时才校验或创建
  映射派生资源。
- 通用数据资源可直接进入既有自然语言分析、派生表格和受控 ECharts 流程；存在资源或字段歧义时先显示选择卡，
  输出保存源资源血缘。
- 数据 alias 在会话内按引擎标识符归一规则唯一，且不得冲突保留字、模型/结果/函数或临时变量；Struct 输入名可以
  由绑定该输入的数据资源作为 alias 使用。引擎升级
  引入冲突时标记 `needs_rename` 并阻止新绑定，不自动重命名资源或改写脚本。
- Struct 输入通过 schema 驱动的参数卡片填写，Data 输入通过上传资源选择；输入未收集完整或用户未显式确认时
  不生成脚本。
- 同一需求对应多个门面时，对话展示候选研究选择卡片，并说明各函数的适用场景、输入、限制和结果差异。
- 用户明确指定算法、研究方法或 `ds_*` 函数时直接采用对应有效门面，不得自动降级或替换，最终摘要仍需确认。
- 一个 Data 输入存在多个兼容资源时，对话显示资源选择卡片及名称、alias、schema、行数、时间范围和来源差异。
- 一个 Data 输入只有一个兼容资源时自动预选，并在最终配置摘要中显示且允许用户更换；没有兼容资源时要求上传。
- 列名或 dtype 可可靠适配时显示受控列映射和类型转换卡片，只有用户确认后生效，歧义或不安全转换不得自动执行。
- 确认映射后创建新的不可变规范化资源并保存源资源、schema、转换 spec 和 engine snapshot 血缘，源资源不被覆盖。
- 多结果门面在确认前显示结果选择卡片并默认勾选引擎目录推荐结果，最终配置摘要冻结用户实际选择的结果集合。
- 用户要求修改参数时打开上一次配置预填的 `para` 卡片；再次确认会生成并执行新脚本，保存来源和参数差异以支持
  修改前后比较，不改写旧脚本或旧结果。
- 参数修改来源唯一时直接使用；存在多个合理候选时显示已有仿真配置选择卡片，不按“最近一次”静默猜测。
- 参数修改后的成功运行不自动生成比较；用户说明比较指标后，Agent 才按明确的两个 run ID 创建分析和可视化。
- 用户确认完整配置后，后台生成受管脚本并立即执行；非零退出码按配置上限自动修正，成功在同一轮返回最终脚本和
  结果，耗尽后保留最后候选脚本并在对话中返回失败原因。
- 成功脚本显示“运行”，点击后单次执行并产生新结果，失败时直接显示错误且不修正；失败脚本显示“重新尝试”，
  点击后从最后候选脚本开始新的执行工作流和修正预算。
- 点击“重新尝试”时先比较上次冻结输入与当前模型/alias 绑定；未变化直接执行，变化时显示差异并经用户确认后
  冻结新输入，缺失或不兼容输入阻止重试。
- “重新尝试”只比较当前门面的 `facadeContractHash`；合同未变可在新 snapshot 下继续，合同变化返回
  `study_contract_changed` 并要求重新规划，普通“运行”不恢复 binary 版本拦截。
- 成功脚本再次“运行”时绑定点击时门面实际需要的最新 active 模型（如有）和全部所需数据资源，包括当前 `para`；
  每次运行冻结实际输入 ID/hash。没有模型输入的门面不要求 active 模型。
- 最终确认事务冻结首次工作流实际使用的精确模型（如有）和数据资源 ID/hash；脚本生成及自动修正期间的输入变化不影响首次执行，
  成功脚本后续点击“运行”时才重新解析最新输入。
- 自动修正使用单个实时进度卡显示阶段、attempt 序号和耗时；每轮脚本与错误详情默认折叠，终态显示结果或失败原因。
- 成功终态只列出结果数据集及查看/下载入口，不自动打开表格、图表或分析；进一步处理由用户用自然语言提出。
- 非终态进度卡提供“取消”；取消停止当前及后续工作、保留历史、清理未提交结果，并允许随后“重新尝试”。
- 页面刷新、断开或切换会话不取消服务端工作流；返回会话后恢复同一进度，重连不得重复执行或重置修正预算。
- 同一会话最多一个非终态受管工作流，第二个请求返回 `workflow_in_progress` 且不自动排队；只读查看功能保持可用。
- 服务重启把非终态工作流收敛为 `service_restarted` 失败并显示“重新尝试”，保留已持久化历史但不自动续跑。
- 默认允许 3 次模型修正、最多 4 次 tensoreval 执行；每轮脚本、退出码和 stderr 均有不可变审计记录。
- 成功还要求所有已确认结果存在、Parquet 可读且 schema 合法；合法零行表允许，缺失或损坏结果以
  `result_contract_invalid` 失败且不发布部分结果。
- 每次运行默认最多 100 个结果、单文件 512 MiB、总量 2 GiB；超限先清理私有结果并返回稳定错误，全部结果通过
  安全和合同校验后才进入用户配额事务。
- adapter 在 tensoreval 运行期间监控私有结果目录，超限或出现禁止路径立即终止进程组；退出后仍执行最终严格扫描，
  监控失败以 `result_monitor_failed` 终止运行。
- 实际结果名称集合必须与用户确认集合完全一致；缺失、重复或额外结果都属于 `result_contract_invalid`。
- 受管脚本冻结创建时的结果名称与 schema；后续“运行”即使调用当前 tensoreval 也沿用该合同，当前输出不一致时
  直接失败，不能用新目录合同重新解释旧脚本。
- 初次生成和后续修正属于同一个 Agent 脚本；用户只看到最终内容，内部 attempt 不形成多个普通脚本资源。
- 原始 stderr 仅进入后端受限审计；外部模型和用户看到保留修错信息但移除服务器路径与敏感值的脱敏版本。
- 脱敏 stderr 默认最多发送和展示 64 KiB；超限时按 UTF-8 边界保留首尾、标明省略字节数，并审计截断前后 hash
  与字节数。
- adapter 对 stdout、stderr 分别流式捕获最多 1 MiB，持续排空超出内容并记录完整流 hash、总字节数和截断状态，
  不得通过无界缓冲读取引擎输出。
- 自动修正只能调整 RSS 表达和同一门面的调用方式；研究函数、算法、输入 alias、Struct 参数和结果集合必须与用户
  确认配置一致，并由结构检查阻止修正模型改变研究目标。
- 初始生成候选违反修正合同时保存 attempt、跳过 tensoreval 但不占修正预算；修正模型返回的违规候选计入一次修正
  预算并保存 attempt，同样不调用 tensoreval；诊断进入下一轮，预算耗尽后工作流直接失败。
- 外部模型的超时、限流和服务端错误由 `AGENT_MODEL_RETRY_MAX=2` 独立退避重试，不消耗脚本修正预算；耗尽后按
  生成或修正阶段返回稳定的模型不可用错误，并保留最后候选和审计历史。
- tensoreval 超时必须终止进程组、清理未发布结果并以 `engine_timeout` 直接失败，不进入自动修正或发布部分结果；
  默认超时由 `TENSOREVAL_TIMEOUT_MS=120000` 控制。
- 自动修正只用于研究确认流程生成的受管脚本；手写、粘贴或上传的 `.rss` 单次执行后直接返回成功结果或失败诊断。
- 上传、粘贴或保存手写 `.rss` 只创建脚本，不自动执行；用户点击脚本卡片“运行”后才执行一次。
- 手写脚本使用开放结果合同：至少一个名称唯一、可读且未超限的 Snappy Parquet；实际 schema 随运行保存，空目录
  返回 `no_result_dataset`，任一非法结果使整次运行失败且不发布部分数据。
- 研究类型、函数参数、参数卡片和上传资源校验均来自本次启动发布的
  `$SPARROWZZ_DIR/dss/docs` snapshot，zjudss 不保存与其竞争的固定函数目录。
- 新 engine snapshot 发布后，新规划重新校验模型和数据兼容性；不兼容数据按目标 schema 标记 `needs_mapping` 并
  通过新派生资源适配，不兼容模型通过新草稿/版本修复，历史脚本和运行不被改写。
- engine resource snapshot 是不计入用户配额的系统级共享 artifact；当前版本和仍被历史资源引用的旧版本必须保留，
  无引用且非当前版本时才允许回收，旧版本不得用于新规划。
- 权威目录发布的全部 DataFrame 研究门面均可进入统一的需求确认和脚本生成流程；路径或 URL 导入门面不进入该流程。
- 门面按目录声明绑定自己的输入集合；含 `network[20]` 的门面从 active 模型逐项取表，没有 model 输入的门面可在
  没有 active 模型时使用普通数据资源执行，不能为统一 arity 强制注入 20 张网络表。
- 单个门面合同无效时只有该门面被禁用；其他有效门面继续可用。用户请求该研究时，Agent 在对话中显示具体诊断。
- 同一会话中数据资源的 alias 唯一，运行记录可追溯到精确的资源 ID 与内容 hash。
- 删除任一资源或重新上传普通数据不改变已经创建的运行及其历史结果。
- 两个用户不能枚举、读取、绑定或猜测对方的数据资源。
- V4 从空数据库初始化，不包含 V3 schema/data 迁移或兼容分支。
