# 全仓库分子系统维护性重构设计

## 1. 意图

在不突破配电网仿真智能体安全边界的前提下，对 Rust/Axum 后端、React/TypeScript 前端、测试基础设施和当前文档进行一次全仓库维护性重构。工作按依赖顺序拆成可独立验收的子系统，不做一次性大改。

本项目允许协调修改 REST/SSE、DTO、稳定错误码、数据库空库 schema、Agent 工具和用户界面，也允许合并或删除重复功能；不为旧客户端、旧数据库或被删除协议增加兼容层。每项公共变化必须在同一子系统内完成调用方迁移、行为测试、功能目录和当前文档更新。

## 2. 成功标准

- 每项领域事实、校验规则、状态迁移和序列化合同只有一个明确所有者。
- 重复实现优先删除，其次复用现有实现，最后才引入新的共享抽象。
- 大文件按职责拆分，而不是按任意行数拆分；拆分后的模块有稳定输入输出和定向测试。
- 前后端不再分别猜测同一领域规则；服务端拥有领域与权限事实，前端拥有本地交互和确定性展示适配。
- 测试夹具表达业务场景，不复制生产算法；公共合同由真实行为测试而非枚举测试单独证明。
- 当前文档各有唯一职责，跨文档只链接权威说明，不成段复制易漂移的事实。
- 每个子系统完成时仓库可构建、相关测试全绿，并有独立提交；阶段末运行全量确定性门禁。
- 用基线和阶段报告记录消除的重复、删除的死代码、模块职责变化及公共合同变化，但不以减少行数作为目标。

## 3. 非目标与反目标

- 不借重构新增与维护性无关的产品功能。
- 不重写技术栈，不把 Rust、React、SQLite、Parquet 或 ECharts 替换为新框架。
- 不建立万能 repository、万能 service、全局错误枚举或为“以后可能复用”设计的抽象层。
- 不合并仅仅语法相似、但所有权、事务、错误码或生命周期不同的实现。
- 不恢复 V3 协议、CSV 结果链路、固定 metrics、任意 ECharts option 或聊天 Agent 脚本/图表创建权限。
- 不通过放宽真实 eig-rs、tensoreval 或资源 snapshot 校验来获得绿色测试。
- 不为当前空库基线设计旧 schema 迁移或双读兼容。

## 4. 不可突破的边界

以下约束高于任何去重收益：

1. 所有 tensoreval 进程调用只能位于 `backend/src/adapters/`。
2. 仿真和派生结果以 Snappy Parquet 为事实来源；生产运行显式使用结果目录和 Parquet 输出。
3. 浏览器和 LLM 只传稳定资源 ID 与受控 spec，不接收服务器路径、命令、SQL、任意脚本执行面或任意 ECharts option。
4. 发布后的 artifact、模型版本、脚本、结果、分析和图表资源不可原地修改。
5. repository 查询显式接收 `UserId`；跨用户与不存在资源统一 404。
6. `SPARROWZZ_DIR` 只读；服务验证并发布不可变资源 snapshot，不修改外部工作树。
7. Agent 按需加载 engine 文档和 skill；真实运行保存实际 bundle、skill refs 与 engine contract。
8. 领域写操作继续遵守自然语言与固定按钮的权限分工；任何调整必须在新合同中明确且可见。
9. 公共路由、消息、工具、skill、上传格式、视图或稳定错误码变化时，同步更新功能目录、行为测试和当前设计文档。

## 5. 已选择的推进方式

### 方案 A：按技术层横向重构

依次整理数据库、application、API 和前端。它容易发现同层重复，但会让一个用户流程跨多个阶段处于不完整状态，回归定位也较差。

### 方案 B：按业务流程纵向重构

依次整理认证、上传、模型、研究、运行、结果等端到端流程。每一步容易验收，但跨业务公共代码会在多个阶段反复调整。

### 方案 C：依赖优先的混合方式（采用）

先收敛经证据证明的跨域基础结构，再逐个整理端到端业务子系统，最后统一 API、前端状态、测试和文档。它兼顾共享代码稳定性和每阶段可运行性，代价是必须严格控制基础抽象的范围。

## 6. 重复代码判定规则

只有满足下列至少一项，才把相似代码视为可消除的重复：

- 同一领域规则在多个位置独立判断，且变化时必须同步修改。
- 同一 DTO、状态迁移、事务步骤、资源引用结算或错误映射被重复构造。
- 多个调用点只在数据参数不同，所有权、失败语义和生命周期相同。
- 测试夹具重复搭建同一合法对象或场景，导致合同更新需修改多处。
- 文档在多个当前文件中重复维护同一个精确枚举、数量或行为定义。

以下情况保留独立实现：

- 不同领域边界需要不同稳定错误码或审计信息。
- SQL 看似相似但事务锁、所有权连接、状态条件或引用释放不同。
- 六类图表、不同上传来源或不同工作流阶段具有真实算法差异。
- 前端展示适配与后端领域编译承担不同信任责任。

每个子系统开始时先列出候选重复点，并为每项选择“删除、复用、抽象、保留”之一及理由。不得先创建通用层再寻找使用者。

## 7. 公共合同和功能调整政策

- 可以修改路由、DTO、错误码、数据库表、Agent 工具和 UI 信息架构，但生产者与全部仓库内消费者必须在同一任务中迁移。
- 可以合并或删除功能；删除必须证明它没有独立用户结果、与另一能力重复或违反新的单一所有权，并删除相应路由、状态、测试和文档，而不是留下空壳兼容入口。
- 仍有独立用户价值但入口重复时，保留一个权威入口并迁移 UI/Agent 调用。
- 数据库继续只支持空库初始化；schema 调整直接修改 initial migration、schema 模型和空库测试。
- 稳定 ID 继续作为跨层边界。物理路径、artifact 内部 ID 和私有诊断不得因接口简化而泄漏。
- 任何功能删除或公共合同变化都必须在子系统设计/计划中显式列出，并在阶段总结中给出替代路径或删除理由。

## 8. 子系统顺序

### 8.1 基线、公共类型、错误与测试夹具

建立仓库维护性基线和权威所有者清单；识别跨层 DTO、ID、分页、时间、错误映射及测试对象构造的真实重复。只提取至少有两个稳定消费者且语义一致的基础结构。保留领域错误边界，不创建全局万能错误类型。

交付物包括模块/合同所有权表、重复候选清单、阶段指标、统一测试 builders/fixtures，以及后续子系统引用的最小公共类型。

### 8.2 Artifact、数据库与仓储

整理 CAS 提交/读取/释放、配额、引用计数、用户作用域查询、事务和 tombstone 生命周期。统一完全相同的 artifact 元数据、所有权 gate、游标与状态迁移；保留具有不同锁、表约束和释放语义的事务。

允许重新组织 initial migration 和 repository 接口，但必须保持不可变资源、逐引用结算、原子发布、跨用户 404 和崩溃恢复边界。

### 8.3 引擎 adapter、资源目录与导入

收敛进程启动、双流有界捕获、取消/超时、结果扫描、catalog/manifest 验证、snapshot 发布、归档与 DataFrame 导入中的公共规则。所有命令构造继续封装在 adapter；资源树继续只读。

案例 projector、普通模型导入和运行结果扫描可以共享底层安全原语，但不得混淆各自输入合同和公开诊断。

### 8.4 上传、模型版本与数据资源

整理 upload batch 状态机、候选用途、幂等操作、草稿/版本发布、资源 replacement、Struct preview 和删除影响。目标是让发布、引用转移、冲突处理和 receipt 构造各有单一实现，消除 application/repository/API 之间重复推断。

允许合并重复入口或重新设计 DTO；案例整体切换与普通上传双子事务若保留不同语义，必须由明确的策略边界表达，而不是条件散落。

### 8.5 研究配置、工作流、脚本与运行

整理 revisioned 配置、输入冻结、私有 Struct overlay、结果选择、工作流 attempt、脚本生成/修正、retry/rerun 和普通运行。统一冻结输入、replacement 血缘解析、失败诊断、状态收敛和取消语义；保留对话 Agent、ScriptAuthor、FailureAnalyzer 与 engine worker 的权限隔离。

可以合并重复的重跑/重试路径或 UI，但最终确认门禁、不可变脚本/运行快照和受控修正预算必须继续可验证。

### 8.6 结果读取、分析、比较与图表

统一 DataFrame schema/分页/投影/下载、来源快照、派生血缘、删除后读取和 artifact 生命周期。分析、比较和图表共享只读数据访问与来源描述，不复制列解析和用户作用域规则。

图表前端 builder 要拆出纯配置状态、字段映射和模板控件；后端 compiler 按职责拆分公共候选/聚合/排序与各图形算法。相似图形不得因追求文件数量而合并算法。服务端继续返回稳定受控模型，前端只做确定性 ECharts 适配。

### 8.7 Agent、工具、Prompt 与知识资源

让工具注册、manifest、Prompt 权限、skill metadata 和实际实现只有一个权威来源，删除重复枚举与陈旧能力。工具继续只接收稳定 ID 与受控参数；按需知识加载和 ScriptAuthor/FailureAnalyzer 隔离不变。

允许合并或删除重复工具，但必须同步 bundle 版本、工具/skill 注册测试、功能目录和运行 provenance。

### 8.8 API、前端状态与界面整合

在前述领域接口稳定后，统一 handler DTO 映射、错误响应、请求代次、分页 state、影响确认、loading/error/retry 和响应式组件。删除只转发数据或重复维护领域状态的层；共享组件只承载相同交互语义。

允许重新组织导航和合并重复界面，但高频无歧义按钮与自然语言领域写操作的权限分工必须明确。所有交互保持键盘可达、390px 无横向溢出，并覆盖加载、空、失败、竞争和恢复状态。

### 8.9 全局测试、部署与文档收敛

删除只验证枚举而不验证行为的冗余测试，保留注册表双向一致性门禁；将重复 fixture 收敛到场景 builders，同时禁止测试复刻生产算法。重建功能目录，使每个当前公共合同恰好有行为证据。

当前文档职责调整为：

- `docs/architecture.md`：稳定系统边界、模块所有权和主数据流。
- `docs/api-design.md`：当前公共 HTTP/SSE 合同及 DTO/错误语义。
- `docs/db-design.md`：空库 schema、持久化不变量和事务所有权。
- `docs/frontend-design.md`：当前用户流程、状态与响应式/无障碍行为。
- `docs/agent-prompt-skills-design.md`：Agent 权限、工具、Prompt 和知识加载。
- `docs/integration-testing-design.md`：测试分层、行为证据和失败政策。
- `docs/v4-deployment.md`：配置、启动、重置、真实依赖和发布操作。
- `docs/development-status.md`：仅记录当前实现、已知阻塞和最近验证证据，不重复完整设计。
- `docs/v4-tester-guide.md`：面向人工测试者的可执行步骤，不承担架构定义。

精确路由、工具、skill、错误和测试数量从 manifest/catalog 自动产生或只在一个当前文档中维护；其他文档引用权威来源。

## 9. 每个子系统的固定工作流

1. 读取当前代码、权威文档、功能目录和最近验证状态。
2. 记录基线：模块职责、公共合同、相关测试、最大文件和重复候选。
3. 为该子系统写实施计划，逐项说明删除、复用、抽象或保留。
4. 先增加或调整行为测试，证明重构前后的预期，而不是锁定私有实现。
5. 小步修改，每一步保持编译或聚焦测试可运行；公共变化在同一步迁移所有消费者。
6. 更新当前设计文档、功能目录和必要的部署/测试指南。
7. 运行聚焦测试、该子系统全量测试和适当的跨层旅程。
8. 独立审查后提交；提交只包含当前子系统拥有的文件和必要的共享迁移。
9. 阶段末运行全量 fmt、Clippy、Rust、Vitest、生产构建、Playwright 和功能覆盖，再进入下一子系统。

若一个重复点跨越尚未开始的子系统，当前阶段只建立清晰接口或记录后续项，不提前重写未来子系统。

## 10. 验证与发布政策

每个子系统至少通过：

- Rust 改动：聚焦测试、`cargo fmt --all -- --check`、相关 target 的严格 Clippy。
- 前端改动：聚焦 Vitest 与 `npm run build`；用户流程变化增加真实 Playwright。
- 公共合同变化：更新 contract manifest、功能目录并运行 `./scripts/check-functional-coverage --require-pr`。
- 数据库变化：空库迁移、约束、事务回滚、用户隔离和恢复测试。
- Agent/engine 变化：工具/skill 双向注册、Prompt 权限和真实边界测试。

阶段末运行 AGENTS.md 中的全量确定性命令。真实 `eig-rs`/tensoreval/LLM 门禁只在相关子系统或候选发布阶段运行；外部资源不一致必须独立报告，不能通过放宽 zjudss 校验掩盖。

当前已知相邻 eig-rs snapshot 含 7 个 `case_projection_invalid` 案例。该外部阻塞作为基线事实保留，直到资源仓库修复并重新验证；维护性重构不得把它误写成仓库代码回归或候选发布全绿。

## 11. 风险控制

- **抽象过度：** 新共享抽象必须有至少两个同语义消费者，并由测试证明共同合同。
- **公共变化扩散：** 路由/DTO/schema/tool 改动必须在一个子系统提交内迁移全部仓库内消费者。
- **删除误伤：** 删除前搜索运行时注册、持久化引用、测试证据和文档；阶段总结列出删除内容与替代路径。
- **事务退化：** repository 重构必须覆盖并发、回滚、幂等、引用结算和崩溃恢复，不以单元测试代替数据库行为测试。
- **权限泄漏：** 任何共享 service 都不得绕过 `UserId`、稳定 ID、Agent skill gate 或 adapter 边界。
- **大文件搬家无收益：** 只有职责或重复所有权得到改善才拆文件；纯移动不计为完成。
- **文档再次漂移：** 每个事实指定一个当前权威文件，其他文档链接而不复制精确枚举。

## 12. 计划与交付方式

本设计是仓库级路线图，不生成一个覆盖全部阶段的巨型实施清单。设计获批后先为“基线、公共类型、错误与测试夹具”编写独立实施计划；该子系统完成并通过阶段门禁后，再基于新的代码现状为下一子系统写计划。

每个计划都必须可以独立产生可运行、可审查的软件，并明确：修改文件、接口变化、删除项、TDD 步骤、验证命令和提交边界。后续计划不得用本设计中的预期状态覆盖已经实现并验证的新事实。
