# 工作区模型区块折叠设计

> 状态：已实现。本文只调整前端展示，不改变 HTTP API、DTO 或模型生命周期。

## 意图

当前模型和可变草稿通常各包含 21 张 DataFrame，工作区会立即渲染全部表卡片，挤占右侧面板空间。用户需要先看到模型摘要，再按需展开具体表格。

## 目标与约束

- “当前模型”和“可变草稿”使用相同的展开/收起交互，并且进入会话时默认收起。
- 两个区块独立控制；展开一个不会改变另一个。
- 收起时仍显示足以识别模型的摘要：当前模型显示版本号、表格数量和总行数；草稿显示修订号、表格数量和总行数。
- 点击区块标题按钮切换状态，按钮提供准确的可访问名称和 `aria-expanded`。
- 切换会话时两个区块恢复默认收起；同一会话内 workspace 刷新不覆盖用户当前选择。
- 展开后的表名、行数、字段数、“查看”操作以及草稿“生成版本”行为保持不变。
- 没有 active 或 draft 时继续显示原有空状态，不显示无意义的折叠按钮。

## 方案

采用与版本历史一致的受控 React 状态：在 `WorkspacePanel` 内分别保存当前模型与可变草稿的展开状态，并在 `sessionId` 变化时重置。摘要由现有 `tables` 数据即时计算，不新增请求。

未采用原生 `<details>`，因为其样式和状态重置不如现有受控按钮一致；未采用手风琴模式，因为两个区块没有互斥关系。

## 验证

- 组件测试先证明 active 和 draft 默认不渲染表卡片，只显示各自摘要。
- 分别展开两个区块，验证 `aria-expanded`、表格查看按钮及草稿发布按钮恢复可用。
- 收起其中一个区块，验证另一个区块保持展开。
- 切换 `sessionId`，验证两者恢复收起。
- 运行完整前端 Vitest 与生产构建。
