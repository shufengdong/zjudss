# 运行记录详情设计

## 意图

当前运行记录只显示运行 ID、英文状态、模型版本 ID、脚本 ID 和创建时间；点击记录会直接打开第一个结果数据集。
用户无法从列表判断本次计算是什么、耗时多久、失败在哪里，也无法选择同一次运行产生的其他结果。

本设计把每条记录改成默认收起、可独立展开的执行摘要：失败时说明失败阶段和原因；成功时列出全部仍可用的结果
数据集并允许逐个打开；排队或运行中显示当前阶段和动态耗时。记录继续承担复现证据，不提供删除运行的操作。

## 目标

- 使用中文状态与阶段，让用户一眼判断运行处于排队、计算、结果收集、成功或失败。
- 显示脚本名称、模型版本、创建/开始/结束时间和耗时，内部 ID 降为次要信息。
- 若运行来自受管研究计划，使用冻结审计信息显示“静态潮流、时序潮流、短路、谐波、电机暂态”等标题。
- 成功记录展开后按需读取该运行的全部存活结果数据集，显示名称、行数和大小；每个数据集都可单独打开。
- 失败记录展开后显示失败阶段、稳定错误原因、退出码（存在时）和耗时。
- 列表加载、结果加载都有明确的 loading、empty、error 和 retry 状态。
- 数据集删除后刷新已展开记录，不能继续展示已经删除的结果入口。

## 非目标与反目标

- 不在运行卡片中读取或预览 Parquet 数据行；实际数据仍由 `DatasetWorkbench` 按需读取。
- 不为不同研究类型硬编码电压、故障电流、THD 等固定指标；结果事实仍是 Snappy Parquet 数据集。
- 不新增自动运行、重跑、删除运行或删除全部结果按钮。
- 不把脚本全文、服务器路径、命令、SQL、原始 stderr 或任意图表配置放入运行记录。
- 不恢复已删除结果的正文；删除后的结果不再可打开。
- 本次不增加运行历史分页，继续使用现有最多 50 条会话运行记录。

## 已选择方案与备选方案

### 方案 A：列表内始终展开全部结果

成功记录立即加载全部数据集，操作直接，但长会话会产生大量请求和很长的侧栏，失败与运行中的信息层级也不清晰。

### 方案 B：可展开卡片，详情按需加载（已选择）

收起态保持紧凑；展开成功记录时才加载结果数据集，失败和运行中不发起无意义的数据集请求。它兼顾信息密度、性能和
移动端空间，也是现有右侧结果面板中最自然的渐进增强。

### 方案 C：独立运行详情窗口

空间最充足，但查看任意结果都多一层导航，也会与当前 DatasetWorkbench 模态层叠。本次不采用。

## 数据与 API 合同

不新增路由、不修改数据库 schema。保留：

- `GET /api/sessions/{id}/runs`：读取会话运行摘要；
- `GET /api/runs/{id}`：读取单个冻结运行；
- `GET /api/runs/{id}/datasets`：读取该运行全部未删除的数据集元数据；
- 现有数据集详情、分页和下载路由不变。

运行 JSON 增加 `scriptName`。该名称来自同会话不可变 `script_resources`，由服务端按用户作用域组装；创建、单条读取和
列表三个响应保持一致。数据库中的脚本 ID、artifact/hash、模型版本/hash、Agent bundle/skill refs、状态、阶段、错误和
时间戳继续原样冻结，不做迁移。

前端 `SimulationRun` 同步增加 `scriptName: string`。研究标题只从运行已经冻结的 `agentSkillRefs` 中读取
`kind=study-plan` 的 `function`，使用受控映射：

- `ds_radial_pf` / `ds_newton_raphson_pf` → 静态潮流；
- `ds_radial_qsts` / `ds_newton_raphson_qsts` → 时序潮流；
- `ds_fault_study` → 短路计算；
- `ds_harmonic_study` → 谐波分析；
- `ds_motor_dynamics` → 电机暂态。

没有合法研究审计信息时以脚本名称作为标题，不根据名称猜研究类型。

耗时由冻结时间戳计算，不新增持久字段：终态使用 `finishedAt - (startedAt ?? createdAt)`；运行中使用当前时间减
`startedAt ?? createdAt`；排队使用当前时间减 `createdAt`。负值和无效时间显示 `—`。运行中卡片用一个共享的低频计时器
刷新展示，不轮询后端；真实状态仍由现有消息/SSE 触发的运行列表刷新决定。

失败原因只读取服务端受控映射后的公共 `error.code` 和字符串 `error.message`，提供安全 fallback，不渲染未知 JSON、HTML、
stderr、服务器路径或调用栈；读取旧运行时也不得透传其中保存的原始 message。失败状态保留最后一个实际执行阶段，旧记录的
`failed` 阶段明确显示为“未知失败阶段”。

## 前端交互

每条记录默认收起并独立保存展开状态；切换会话时清空。卡片头部是原生 button，并使用 `aria-expanded`：

```text
静态潮流                         成功
power-flow.rss · 模型版本 3
耗时 1.8 秒 · 2026-10-25 14:32
                         [展开详情]
```

展开后的成功记录显示：

```text
计算结果（2）
bus_phase        128 行   24.1 KiB   [查看]
summary            8 行    3.2 KiB   [查看]

运行 #9 · 脚本 #4 · Engine tensoreval-parquet-v3
```

“查看”直接打开所选数据集，而不是固定打开第一个。首次展开进入 loading；失败显示“结果加载失败”和重试按钮。接口返回空数组时
显示“本次运行没有可用结果，结果可能已被删除”。卡片再次打开时允许使用当前缓存；数据集删除成功后由 App 提升一个
`datasetRevision`，使所有缓存立即失效、已展开成功记录重新读取；当时收起的记录在下次展开时读取，避免陈旧入口。

展开后的失败记录不请求数据集，显示：

```text
失败阶段：执行计算
失败原因：<安全的 error.message>
退出码：<存在时>
耗时：0.7 秒
```

运行中记录显示当前阶段和已运行时长；结果区显示“计算完成后可查看结果”。状态/阶段映射未知值时显示安全的“未知状态”或原始
受控 stage 文本，不把未知状态误报为成功。

## 状态管理与错误处理

- `useRunHistory` 从裸数组升级为 `{runs, status, error, reload}`，继续用 generation 防止切换会话后的迟到响应覆盖。
- 运行列表请求失败不能伪装成“暂无运行记录”；界面提供重试。
- 结果详情按 run ID 维护 loading/data/error；同一记录并发请求只接受最新一代响应。
- `datasetRevision` 变化时只刷新当前展开且已成功的记录，不自动展开其他记录。
- 新的 progress/result 消息继续触发现有 run list 刷新；收起状态不因刷新丢失。
- 数据集打开仍使用稳定 `datasetId`，不传路径或任意查询。

## 可访问性与响应式

- 卡片展开按钮使用可见标题作为 accessible name，并暴露 `aria-expanded`、`aria-controls`。
- 状态不只依赖颜色，同时显示中文文字；失败区域使用 `role=alert`，加载区域使用 `aria-live=polite`。
- 数据集入口使用原生 button，名称包含数据集名；键盘顺序为卡片头、结果入口、重试。
- 窄屏保持单列，名称和错误原因可换行，ID/hash 不造成横向溢出。

## 验证与追溯

- Rust API/应用测试：创建、列表和详情都返回正确 `scriptName`；跨用户和不存在资源仍统一 404；无需数据库迁移。
- Vitest：覆盖成功、失败、运行中、排队、中文阶段、动态/终态耗时、研究标题 fallback、全部数据集、加载失败重试、删除刷新和
  运行列表加载失败。
- Playwright：成功运行展开后可选择非首个结果；失败运行展示原因且不请求结果；运行记录仍无删除按钮；窄屏与 axe 无回归。
- 更新 `docs/api-design.md`、`docs/frontend-design.md`、`docs/integration-testing-design.md`、公共 DTO 和
  `integration-tests/catalog/features.yaml`。这是现有 RUN view/route 的行为增强，不新增 route、message、tool、skill 或 view 枚举。

## 实施者可自行决定

- 中文状态徽标的具体颜色、间距和图标；
- 字节与耗时格式化函数的内部位置；
- 运行卡片详情缓存使用组件 state 还是专用 hook，只要满足请求代次与删除刷新约束。
