# 大结果上限与流式下载设计

## 目标

- 仿真结果单文件上限统一为 2 GiB（`2147483648` 字节）。
- 单次运行全部结果上限统一为 8 GiB（`8589934592` 字节）。
- 结果始终完整发布；超过限制时明确失败，不截断、不抽样、不发布部分结果。
- 所有受保护文件下载均从已授权文件句柄流式响应，浏览器下载结果时不先构造完整 `Blob`。

## 边界

结果继续使用单个不可变 Snappy Parquet artifact，不引入分片、数据库迁移、新路由或新消息类型。后端下载响应保留现有
`Content-Type` 与 `Content-Disposition`，增加准确的 `Content-Length`，并以固定大小块读取文件。结果工作台使用同源下载链接，
由浏览器直接写入下载目标；数据资源和模型表保持现有前端错误处理，但同样受益于后端流式响应。

## 验证

- 配置测试证明缺省单文件为 2 GiB、总结果为 8 GiB，且总量小于单文件仍被拒绝。
- 下载 helper 测试证明响应包含准确长度并产生多个有界数据块，而不是单个完整文件块。
- 结果工作台测试证明下载入口直接指向受保护 dataset 下载路由，不调用 Fetch/Blob 下载函数。
- 后端格式、Clippy、完整测试以及前端完整测试和生产构建全部通过。
