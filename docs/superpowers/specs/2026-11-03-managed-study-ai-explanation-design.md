# 受管研究 AI 详细说明与可折叠配置卡设计

## 意图

恢复研究配置创建前由大模型生成的个性化详细说明，同时保留已经修正的因果顺序：

`AI 详细说明 → 研究配置卡 → 研究工作流 → 研究成果`

用户需要的不是固定模板提示，而是大模型结合本轮原始意图、目录搜索结果和选定门面对研究方案作出的说明。说明必须在配置卡之前稳定出现，不能恢复成可能迟到至工作流或成果之后的 provider 尾声。

研究配置卡可能包含较多输入、参数和结果，持续占用对话区屏幕。卡片首次出现时仍应展开以便用户发现并处理必填项，但用户可以从标题栏收起；在当前浏览器会话内重新渲染、切换会话或刷新页面时保留每张配置卡的折叠选择。

## 目标

- 说明内容仍由当前对话大模型生成，保留修改顺序前的信息量和自然表达。
- 说明至少覆盖用户意图、选定研究方法/门面、需要用户检查的输入或参数、计划结果以及下一步操作。
- 后端只有在研究配置成功创建后才持久化说明，并按“说明、配置卡”的顺序连续写入 durable 消息。
- 配置标题、稳定配置 ID 和“仍需点击确认并生成脚本”由后端根据实际创建结果补充，不能由模型猜测。
- provider 在工具成功后的自由文本尾声继续抑制，避免重复说明和顺序回归。
- 研究配置卡标题栏提供明确的展开/收起控制，折叠时保留研究标题、revision、状态和操作存在性的简要提示。
- 配置卡首次出现默认展开；用户选择通过 `sessionStorage` 按配置 ID 保存，仅作用于当前浏览器会话。
- mutation 错误、`configuration_stale` 刷新冲突或其他需要用户处理的卡片错误会自动展开，避免错误和必填操作被隐藏。

## 非目标与反目标

- 不允许自然语言说明确认配置、生成脚本或启动运行。
- 不把模型说明当作研究合同；配置卡和服务端目录仍是门面、输入、参数和结果的权威来源。
- 不通过前端按邻近消息猜测关联，也不修改历史消息 ID 或持久化顺序。
- 不延迟配置卡等待 provider 工具调用后的尾声，也不引入配置已创建但卡片尚未发布的新恢复窗口。
- 本次不改变 assistant/study-config 公共消息类型和最终固定 UI 确认门禁。
- 折叠不改变配置状态、不自动提交结果或确认配置，也不隐藏已发生的错误。

## 约束

- `prepare_study` 仍是唯一创建研究配置的 Agent 工具，调用前必须加载 `study-planning`。
- 工具新增必填 `explanation` 文本参数。文本去除首尾空白后必须非空，最长 4,000 个 Unicode 字符；无效参数在领域写入前拒绝。
- 文本允许受控 Markdown，但不得包含服务器路径、命令或声称研究已经确认、脚本已经生成、仿真已经运行等虚假完成状态。
- 模型生成说明时只能依据用户本轮意图和 `search_study_facades` 返回的目录事实；资源绑定和最终选择以随后生成的卡片为准。
- Agent bundle 工具合同发生变化，bundle 版本递增并重新计算 manifest hash。
- 折叠按钮使用原生 `button`、`aria-expanded` 和与当前动作一致的可见文字；配置 mutation 和 SSE revision 更新不能重置用户的折叠选择。

## 已考虑的方案

### 方案 A：说明作为 `prepare_study` 参数（采用）

模型在已经取得目录搜索结果、准备调用工具时生成 `explanation`。工具先校验说明，再创建配置；成功后写入说明及后端权威尾注，随后写入配置卡。

优点是内容来自大模型、顺序由同一个工具确定、provider 收尾失败不影响已显示内容，也不需要新增消息类型。代价是模型生成说明时尚不知道配置 ID；该 ID 正好由后端在成功后补充。

### 方案 B：缓存工具调用后的 provider 尾声，再发布配置卡

这最接近旧生成时机，但会延迟卡片，并在配置领域对象已经创建、provider 或服务进程随后失败时引入恢复窗口。它与 durable 配置卡立即可用的现有合同冲突，因此不采用。

### 方案 C：后端保持迟到尾声，前端重新排序

改动表面较小，但 assistant 消息没有可靠的配置关联；相邻用户消息、并发确认和历史分页都会造成误配或短暂乱序，因此不采用。

### 配置卡折叠方案

采用卡片组件内的受控折叠状态，并通过 `sessionStorage` 以配置 ID 保存。相比只用 React 本地状态，它能在切换会话和刷新页面后保持当前浏览器会话中的选择；相比写入服务端或 `localStorage`，它不会把纯展示偏好扩散到其他浏览器会话、用户或长期历史。首次无记录时展开，出现错误时覆盖存储选择并自动展开。

## 详细行为

`prepare_study` 参数变为：

```json
{
  "facadeId": "目录门面 ID",
  "intent": { "request": "用户原始研究意图" },
  "derivedFromWorkflowId": null,
  "explanation": "大模型生成的个性化研究方案说明"
}
```

模型说明应在一次连贯回答中包含：

1. 对用户目标的简短复述；
2. 选定方法及其与用户要求的关系；
3. 配置卡中需要检查或补齐的输入、参数；
4. 初始计划输出；
5. 明确说明下一步是在卡片中检查并最终确认，而不是已经执行。

配置创建成功后，工具持久化一条普通 assistant 消息：

```text
{模型生成的 explanation}

已创建“{服务端实际门面标题}”研究配置卡（ID: {服务端实际配置 ID}）。请在卡片中检查并确认输入、参数和结果；只有点击“确认并生成脚本”后才会开始执行。
```

紧接着持久化对应 `study-config` 消息。模型在工具成功后的 provider 尾声不再写入。若创建配置失败，则说明和配置卡都不写入；若说明本身无效，则在任何研究配置写入前拒绝工具调用。

配置卡的标题栏始终显示研究标题、revision 和展开/收起按钮。展开时继续显示现有门面选择、输入、Struct 参数、列映射、结果选择、摘要与最终确认按钮；收起时这些交互内容不挂载，只显示一行状态提示，说明需要展开卡片才能继续配置或确认。配置进入 `confirmed` 或 `cancelled` 后继续使用现有紧凑终态展示，不保留无意义的折叠按钮。

## 错误与安全

- 缺少、空白或超过长度限制的说明作为无效工具参数处理，不创建配置。
- 说明不是授权信号。即使文本声称“已确认”或“已运行”，服务端状态机和固定确认按钮仍不会被绕过；Prompt 同时禁止这种表述。
- 后端权威尾注始终使用实际门面标题和配置 ID，避免模型伪造稳定资源标识。
- 说明不接收或输出服务器路径、SQL、shell、任意脚本或任意图表配置。

## 验证

- Rust 工具测试先证明缺少有效说明会被拒绝且不创建配置，再证明个性化说明、权威尾注和配置卡按消息 ID 连续排序。
- scripted-agent 测试证明模型传入的详细说明可见，provider 尾声仍被抑制，provider 收尾失败也不覆盖已经持久化的说明和配置卡。
- Playwright 证明自然语言研究请求最终显示“用户消息 → AI 详细说明 → 配置卡”，且确认、工作流和成果顺序保持不变。
- Vitest 证明卡片默认展开、可从标题栏收起和恢复、revision 更新不重置选择、错误会自动展开，终态卡片保持紧凑。
- Playwright 证明长配置卡可收起、切换会话再返回后仍保持收起，并能重新展开完成最终确认。
- 更新 Agent bundle、设计文档、功能目录和发布断言，并通过 Rust、Vitest、构建、Playwright 与功能覆盖门禁。
